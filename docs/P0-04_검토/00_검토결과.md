## 2. 지시서와 다른 점 — 고쳐야 할 것

### A. 되돌리기 커밋 번호가 틀렸습니다 ⚠️

지시서 7절은 `main` 의 이전 커밋 **`9cd1644`** 를 재배포하라고 돼 있지만,
**운영 저장소에 그 커밋이 없습니다.**

```
$ git cat-file -t 9cd1644
fatal: Not a valid object name 9cd1644
```

맞는 되돌리기 대상은 **지금의 `main` = `7331acf`** 입니다
(이 커밋의 `index.html` 해시가 기준선 `14655ed7…` 입니다).
`docs/P0-04_검토/03_현재_운영_index.html` 로도 보관해 뒀습니다.

### B. 백필 숫자 확인은 "참고"가 아니라 **관문**입니다 ⚠️

새 코드는 `media_url` 공개 URL 폴백을 **지웠습니다.**
그래서 `0003` 백필이 못 읽은 행은 **코드 배포 즉시 사진이 사라집니다**
(`media_path` 가 비어 있으면 `attachMediaUrls` 가 건너뜁니다).

→ 2단계 숫자가 안 맞으면 **3단계(코드 배포)를 시작하면 안 됩니다.**
지시서는 "멈추고 보고"로만 적혀 있는데, 여기서 멈추는 건 선택이 아니라 필수입니다.

### C. mp4 질문은 테스트 없이 답이 나옵니다 ✅

지시서가 "배포 직후 확인" 으로 남겨둔 항목입니다. 결론:

- `allowed_mime_types` 는 **업로드만** 제한합니다. 다운로드·서명에는 영향이 없습니다.
- `isVideoUrl` 정규식 `/\.(mp4|mov|webm|m4v|3gp|avi)(\?.*)?$/i` 는
  서명 URL 형태(`….mp4?token=…`)를 정확히 잡습니다.

→ **기존 mp4 글 3건은 그대로 `<video>` 로 재생됩니다. 새 mp4 업로드만 막힙니다.**
깨진 이미지로 뜨지 않습니다. (배포 후 눈으로 한 번 더 보는 건 여전히 권장)

### D. 이동 스크립트에 자동 복구가 안 되는 틈이 있습니다 ⚠️

`migrate_media_paths.mjs` 는 **파일 이동 → DB 갱신** 순서입니다.
이동은 됐는데 DB `PATCH` 가 실패하면:

- 파일은 새 경로, DB 는 옛 경로 → **그 행 사진만 깨짐**
- **재실행으로 안 고쳐집니다** — 옛 경로에 파일이 없어 `move` 가 또 실패합니다

그 행은 `media_path` 를 새 경로로 **직접 UPDATE** 해야 합니다.
실패 건이 나오면 "아직 안 옮겨짐" 과 "옮겼는데 DB 만 안 됨" 을 구분해 보고하겠습니다.

### E. 파일 이동 후에는 코드 롤백만으로 사진이 안 돌아옵니다 ⚠️

스크립트가 `media_url` 을 `null` 로 지웁니다. 옛 코드는 `media_url` 만 보므로,
4단계 뒤에 코드를 되돌리면 **사진이 전부 사라집니다.**
→ 되돌릴지 판단은 **반드시 4단계 전에.** (지시서 결론과 같지만, 이유가 하나 더 있습니다)

## 3. 알아두실 사용자 눈에 보이는 변화

### F. 커뮤니티 탭을 10분 넘게 열어두면 사진이 깨집니다

서명 URL 만료는 10분(`MEDIA_TTL = 600`)인데, 재발급을 돌리는 `refreshRemote()` 가
**탭 이동·로그인 변화 때만** 실행됩니다. 타이머도 `visibilitychange` 도 없습니다.

- 탭을 한 번 옮기면 바로 복구됩니다
- 차단 사유는 아니지만, **별도 수정 대상**으로 올려둘 값입니다

### G. 사용자가 공유한 사진 링크가 10분 뒤 만료됩니다

공유 버튼이 서명 URL 을 그대로 내보냅니다. P0-04 의 **의도된 결과**이지만
(링크 회수 가능 = 이 작업의 목적), 기존 사용자에게는 달라진 동작입니다.

### H. 기록용 — `0006` 마이그레이션 파일이 저장소에 없습니다

`0005` 다음이 `0007` 입니다. 지시서는 P0-05 를 `0006+0007+0008` 로 적었습니다.
이번 범위와 무관하지만 P0-05 할 때 걸릴 겁니다.

## 3단계 배포 후 확인 — 일부만 가능했음

내장 브라우저로 비로그인 상태의 운영 앱을 확인:

- 페이지 정상 로드, **콘솔 오류 0건** (`permission denied` 류 없음)
- 그런데 **비로그인 피드에 사용자 글이 하나도 없습니다.**
  공지 비어 있음 / 자랑·Q&A 에 글 없음 / 사이트 전체에서 사용자 사진 0건
  (혜택 화면의 제품 사진 3장은 정적 이미지)
- → 지시서의 "비로그인으로 승인된 글의 사진이 보이는가" 는
  **검증할 대상 자체가 운영에 없습니다.**

운영 DB 직접 조회는 세션 안전장치(`Production Reads`)가 차단했습니다.
클라우드 세션이 걸린 것과 같은 제약이고, 우회하지 않았습니다.

## 4단계 전에 결정해야 할 것 — 중요

백필 숫자가 **media 가 걸린 행이 전부 1건**임을 뜻합니다.
그런데 운영 `media` 버킷에는 파일이 **10개**(jpg 6 · mp4 3 · `dadamom.html` 1)입니다.

`migrate_media_paths.mjs` 는 **`media_path` 가 있는 행만** 옮깁니다.
따라서 이동 대상은 **1개**, 나머지 **8개(jpg 5 · mp4 3)는 버킷 루트에 남습니다.**
남은 파일에 대해 예전에 발급된 **2036년 만료 서명 URL 은 계속 열립니다.**

> P0-04 의 목적이 "한 번 나간 사진 링크를 회수하는 것" 인데,
> 4단계를 지시서대로만 돌리면 **9개 중 1개만 무효화됩니다.**

지시서는 남은 파일을 각주로 다뤘지만, 실제로는 이게 **다수 사례**입니다.
남은 8개를 어떻게 할지는 영구 삭제 판단이라 사장님 결정이 필요합니다.

덤으로, 어느 행도 mp4 를 참조하지 않으므로 지시서가 걱정한
"기존 mp4 글이 깨져 보이는지" 는 **해당 글 자체가 없어 무의미**합니다.
(백필 숫자에서 나온 추론입니다 — 행 내용을 직접 못 봤습니다)

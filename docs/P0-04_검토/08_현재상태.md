## 닫힌 것 4가지 — 다시 올리지 마세요

### 1. 4단계 "파일 이동" — **하지 않기로 했고, 할 필요도 없습니다**

지시서는 `scripts/migrate_media_paths.mjs` 로 파일을 `<uid>/` 폴더로 **옮기라**고
했습니다. 실제로는 **전부 지웠습니다.**

이유: 운영 DB 에 사진이 달린 글이 **1건**인데 버킷에는 파일이 **10개**였습니다.
9개가 고아였고, 스크립트는 고아를 건드리지 않습니다. 그대로 돌렸으면 10개 중 1개만
무효화됐을 겁니다. 사장님이 "전부 테스트로 올린 것" 이라고 확인해주셔서 **10개 전부
삭제**로 갔습니다. 옮기는 것보다 확실합니다.

덕분에 `service_role` 키를 쓰는 그 스크립트를 **아예 돌리지 않았습니다.**

**버킷 파일 수: 10 → 0.** 평면 경로에 남은 사진은 없습니다.

### 4. `storage.objects` 의 넓은 SELECT 정책 — **확인 끝났습니다 (2026-10-01 16:47)**

Claude Code 가 "리허설의 `policyname like 'media%'` 필터가 넓은 정책을 가렸을 수
있다" 고 지적했고, 타당해서 **필터 없이** 다시 확인했습니다. 적용 **전**(정책 5개)과
**후**(정책 6개) 양쪽 다 필터 없이 받았습니다.

| 정책 | 동작 | 조건 |
|---|---|---|
| media read published or own | SELECT | `bucket_id='media'` + `media_can_read(name, auth.uid())` |
| album own read | SELECT | `bucket_id='album'` + 본인 폴더 |
| media own upload / album own insert | INSERT | 본인 폴더 |
| media own delete / album own delete | DELETE | 본인 폴더 |

**SELECT 는 2개뿐이고 둘 다 `bucket_id` 로 묶여 있습니다.** `using (true)` 같은 전면
허용은 없습니다. 적용 전에 있던 넓은 정책은 `media public read` 하나였고 그 이름은
`0003` 의 drop 목록에 있어 사라졌습니다. **가려져 있던 정책은 애초에 없었습니다.**

## 그래서 "글 삭제가 파일 이동 뒤에야 동작한다" 도 해당 없습니다

`0003` 의 삭제 정책이 `<uid>/` 폴더 안 파일만 허용하는 건 맞습니다. 하지만 운영에
평면 경로 사진이 **0개**라 걸릴 대상이 없습니다.

2026-10-05 실측 (운영 SQL Editor):

```sql
select count(*) as 사진달린_글,
       count(*) filter (where coalesce(media_path,'') <> '') as 경로있음
  from public.community_posts
 where coalesce(media_url,'') <> '' or coalesce(media_path,'') <> '';
-- 결과: 0 / 0
```

새로 올리는 사진은 처음부터 `<uid>/` 아래로 들어갑니다.

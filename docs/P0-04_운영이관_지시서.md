## 0. 범위 — 이것만 합니다

**올리는 것:** P0-04 (아이 사진 보안) + `0004` (계정 삭제 버그 수정)

**올리지 않는 것 — 중요:**
`staging` 의 `index.html` 에는 **P0-03 과 P0-05 코드가 이미 섞여 있습니다.**
그 기능들의 마이그레이션(`0005`~`0010`)은 운영에 없습니다.
같이 올라가면 **운영 앱이 없는 테이블·함수를 부릅니다.**

`staging` 전체를 `main` 에 머지하지 마세요. P0-04 변경만 골라 옮깁니다.

테스트 전용 4가지도 올리지 않습니다 — `env.js` 참조, TEST 띠,
PWA·서비스워커·`<meta charset>`, `SOCIAL_LOGIN` 분기.
(`<meta charset>` 은 별도 승인 대기 항목입니다. 이번에 넣지 마세요.)

## 2. DB 먼저 (운영 `hjqchbpxwviengdzvado`)

SQL Editor 에서 **반드시 리허설 먼저.**

```sql
-- 1) 리허설: 파일 내용을 begin; ... rollback; 으로 감싸 실행
-- 2) 결과 확인 후 begin; ... commit; 으로 적용
```

적용 순서:
1. `supabase/migrations/0003_media_private.sql`
2. `supabase/migrations/0004_delete_account_storage_fix.sql`

`0003` 이 하는 일: `media_path` 컬럼 생성 → 기존 `media_url` 에서 경로를 뽑아 채움 →
버킷을 private 으로 → 이미지 전용(jpeg/png/webp)·25MB 제한 → `media_can_read()` 와
읽기/업로드/삭제 정책.

**적용 후 바로 확인할 것:**

```sql
select count(*) as 전체,
       count(*) filter (where coalesce(media_path,'') <> '') as 경로채워짐
  from public.community_posts where coalesce(media_url,'') <> '';
select count(*) as 전체,
       count(*) filter (where coalesce(media_path,'') <> '') as 경로채워짐
  from public.challenge_entries where coalesce(media_url,'') <> '';
```

**두 숫자가 같아야 합니다.** 다르면 백필이 못 읽은 `media_url` 형식이 있는 겁니다.
멈추고 그 행들을 보고하세요. **여기서 멈춰도 사용자에게는 아무 영향이 없습니다**
(아직 파일을 안 옮겼으므로 기존 URL 이 그대로 열립니다).

## 3. 코드 배포 (파일 이동보다 **먼저**)

> `docs/PROMOTION.md` 는 파일 이동을 먼저 하라고 돼 있지만, 그렇게 하면
> 파일이 옮겨진 순간부터 코드가 배포될 때까지 **운영의 모든 사진이 깨집니다.**
> 지금 운영 코드는 `media_url`(2036년 만료 서명 URL)만 쓰기 때문입니다.
> 순서를 바꾸면 그 구간이 사라집니다 — 사장님 승인 받았습니다.
> 새 코드는 `media_path` 로 그때그때 서명하므로 파일이 아직 옛 경로에 있어도 정상입니다.

### 옮길 변경 찾기

`staging` 에서 P0-04 를 구현한 커밋을 찾아 그 커밋들의 `index.html` 변경만 가져옵니다.

```bash

git show <P0-04 커밋>:index.html
```

### 옮길 것 (P0-04)

| 심볼·위치 | 내용 |
|---|---|
| `MEDIA_ALLOWED` `MEDIA_MAX_BYTES` `MEDIA_TTL` `mediaUrlCache` | 이미지 전용·25MB·10분 서명·URL 캐시 |
| `uploadMedia(file)` | `{path, error}` 를 돌려주고 `<uid>/` 폴더로만 업로드 |
| `signMediaPaths(paths)` | 경로 → 짧은 서명 URL (캐시 포함) |
| `attachMediaUrls(rows)` | 가져온 행에 서명 URL 붙이기 |
| `resignLocalMedia()` | localStorage 에서 되살아난 글의 만료된 URL 재발급 |
| `fetchEntries()` `fetchPosts()` | `media_path` 를 select 하고 `attachMediaUrls` 통과. **공개 URL 폴백 제거** |
| `handleEntrySubmit()` `handlePostSubmit()` | payload 에 `media_path` 저장 |
| `handleDeleteAccount()` | `my_media_paths` RPC → Storage API 로 파일 삭제 → 그 다음 `delete_my_account()` |
| 파일 입력 2곳 | `accept="image/jpeg,image/png,image/webp"` + "JPG · PNG · WEBP, 25MB까지" 안내 |
| `stripExifIfImage` 호출 | `uploadMedia` 안에서 부름. 이 함수가 운영에 이미 있으면 그대로, 없으면 같이 가져오기 |

## 4. 파일 이동 — 이 단계를 빼면 P0-04 는 의미가 없습니다

서명 URL 은 버킷을 private 으로 바꿔도 죽지 않습니다. 토큰이 RLS 를 거치지 않고,
토큰 안에 경로가 박혀 있어서 **그 경로에 파일이 없어야만** 죽습니다.
운영의 `media_url` 들은 전부 **2036년 만료**입니다.

```bash
export SUPABASE_URL='https://hjqchbpxwviengdzvado.supabase.co'
export SUPABASE_SERVICE_ROLE_KEY='...'    # 환경변수로만. 저장소에 넣지 말 것
node scripts/migrate_media_paths.mjs --dry-run    # 먼저
node scripts/migrate_media_paths.mjs              # 실제
```

**현재 운영 버킷 상태** (2026-10-01 클라우드 세션이 대시보드에서 확인):
파일 10개, 전부 버킷 루트 — jpg 6, mp4 3, `dadamom.html` 1.

스크립트는 `media_path` 가 있는 행만 옮깁니다. 어느 행에도 안 걸린 파일은
루트에 남습니다. 버킷이 private 이 됐으니 공개 URL 로는 못 열리지만,
**그 파일에 대해 예전에 발급된 서명 URL 이 있다면 계속 열립니다.**
이동 후 루트에 남은 파일 목록을 확인하고 보고하세요.

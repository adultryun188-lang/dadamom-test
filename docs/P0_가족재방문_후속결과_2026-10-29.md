## 2. 현재 바로 실행 가능한 재방문 측정

파일:

- `retention-metrics.cjs`: 명시한 코호트와 글·댓글 시각을 입력받는 순수 집계.
- `scripts/p0-retention-report.mjs`: 로컬 최소 JSON 또는 알려진 테스트 계정 3명만 대상으로 집계.

```powershell
node tests/retention-metrics.spec.mjs
node scripts/p0-retention-report.mjs --live-test
node scripts/p0-retention-report.mjs --input C:\경로\최소활동.json
```

입력 예시(모두 가상 값):

```json
{
  "asOf": "2026-11-09T00:00:00Z",
  "cohort": [{"id":"fake-a","joined_at":"2026-11-01T00:00:00Z"}],
  "actions": [{"id":"fake-post-1","user_id":"fake-a","kind":"post","at":"2026-11-02T00:00:00Z"}]
}
```

출력은 코호트 인원, 첫 글/댓글 작성 인원, 7일 관찰 완료/미완료 인원, 관찰 완료자 중 다른 한국 날짜에 7일 이내 작성한 인원과 비율이다. 관찰 시점까지의 활동만 사용하고, 분모 0이면 비율은 null이다.

### 해석 한계

- 현재 원격 읽기는 각 테스트 계정 본인의 프로필 생성시각·글·댓글의 ID/작성자/작성시각만 읽는다. 실제 회원 목록은 읽지 않는다. 관리자 집계 화면을 추가하지 않았다.
- 현재 자료 기반 결과는 **삭제되지 않고 남아 있는 글·댓글 활동의 하한치**다. 삭제된 작성, 가족 초대 열람, 돌봄 기록, 단순 접속, 투표를 복원하거나 섞지 않는다.
- 가입 기준은 명시해야 한다. 프로필 생성·이메일 계정 생성·파일럿 참여 시작은 서로 다르다.
- 기존 `last_seen`은 정확한 7일 내 재행동의 대용으로 쓰지 않는다.
- 실제 파일럿 집계는 운영자·시드·가상 계정을 코호트에서 제외해야 한다. 이번 --live-test는 도구 검증을 위해 가상 계정을 의도적으로 사용한다.
- 이 실행의 예시 결과는 코호트 3, 첫 행동 1, 관찰 완료 3, 7일 재행동 0이었다. 고객 수요가 없다는 의미로 해석하면 안 된다.

## 3. 0044 — 별도 테스트 DB 세션에서 마무리할 일

파일: `supabase/migrations/0044_pilot_activity_days.sql`

설계:

- 명시적으로 파일럿에 등록한 참여자만 수집한다. 일반 회원 전체를 자동 등록하지 않는다.
- 신규 글·댓글의 성공한 INSERT만 서버 시각으로 기록한다. 하루/종류별 최초 시각 1개, 원본 글 삭제와 독립. 원본 ID·본문·사진·아이 정보·초대 코드는 저장하지 않는다.
- 일반 클라이언트의 코호트 등록·활동 조회·변경 권한은 없다. 탈퇴 또는 코호트 삭제 시 cascade로 지운다.
- 기본 수집 기간은 등록 후 30일. 보유 상한 제안은 등록 후 90일이며 매일 정리 작업이 필요하다. **SQL 파일 자체에 자동 스케줄러는 포함돼 있지 않다.**
- 측정 저장 장애가 글·댓글 작성을 실패시키지 않게 SQLSTATE만 경고한다. DB 세션에서 경고 확인과 실제 환경 권한을 검증해야 한다.
- 기존 행을 백필하지 않는다. 등록 전 활동을 수집했다고 가정하지 않는다.

필수 후속 단계:

1. 최신 번호를 다시 확인한다. 0044가 다른 작업에 사용됐으면 다음 번호로 조정한다.
2. 테스트 DB 환경만 확인한 뒤 트랜잭션 리허설 및 롤백, 현재 스키마/트리거 충돌 여부를 확인한다.
3. 실제 가입일과 수집 시작일을 구분한다. 중간에 등록한 기존 계정은 과거 7일 가입 코호트의 완전 관찰자로 집계하지 않는다. 파일럿 참여 시작 기준을 쓰면 출력에 ‘가입 재방문’ 대신 ‘파일럿 참여 후 재행동’이라고 명시한다.
4. 동의한 테스트 파일럿 참여자 범위를 확정하고 등록·중단·탈퇴·90일 정리 절차를 검증한다. 개인정보 수집 안내 수정안과 보유 기간을 맞춘 뒤 수집을 활성화한다. 현재 공개 방침을 임의 변경하지 않았다.
5. 0044 적용 후 가상 계정으로 실제 글·댓글 생성/삭제, 중복, 비참여자, 타인/anon 조회 차단, 탈퇴 cascade와 정리 스케줄 실행을 검증한다.
6. 집계 입력용으로 cohort의 기준시각 및 activity_days의 first_at/kind만 내보낸다. 개인 내용은 내보내지 않는다. `activity_day+kind`를 합성 행위 ID로 사용하고 관찰 시작 이전 결측을 별도로 표시한다.
7. `retention-metrics.cjs`의 coverage를 `pilot-activity-days`로 표시한다. 글·댓글 외 지표를 수집 완료로 표시하지 않는다. 아직 없는 가족 반응 이벤트도 추가하지 않는다.
8. 역방향 SQL은 0044 하단에 있다. 원격 운영 연결·운영 데이터 백필은 하지 않는다.

별도 세션이 필요한 근거: 최신 저장소 [CLAUDE.md](../CLAUDE.md) 6절의 **“Supabase 대시보드 작업(SQL 실행, Auth 설정)과 코드 수정은 같은 세션이 하지 마세요.”** 이 세션에서는 코드·SQL·테스트를 준비하고 로컬 DB로 검증했으며 원격 스키마 적용은 하지 않았다.

## 5. 남은 상태

- 가족 초대·철회 API는 원격 테스트 DB에서 확인 완료. 시간 만료 강제 시험은 로컬, 24시간 자연 만료 원격 시험은 미실행.
- 기존 가족 UI 종합 스크립트는 시작 시 user_app_data를 지우므로 실행하지 않았다. 이번 ‘기존 변경 보존’ 요구에 따라 해당 개인 자료를 초기화하지 않았다. 실제 가족 UI 종합 검증을 완료했다고 표시하지 않는다.
- 가족 기록 접근과 별개인 기존 사진 서명 URL의 캐시·만료·철회는 이번에 새로 검증하지 않았다. 사진을 공개로 바꾸거나 권한을 넓히지 않았다.
- 재방문 집계는 실행 가능. 삭제 후에도 보존되는 신규 일별 활동 수집은 0044를 별도 DB 세션에 적용해야 한다.
- 신규 가입 실제 메일·소셜 계정 최종 인증·iPhone 실기기는 사용자 직접 확인이 남는다.
- 운영 앱·운영 DB·실제 회원 자료는 조회·변경하지 않았다. 이번 코드 변경은 테스트/집계 도구·준비 SQL·문서이며 앱 화면 변경은 없다.

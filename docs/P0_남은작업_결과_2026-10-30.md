## 3. P0-4 사진 권한·서명 URL — 확인한 사실

- 가족 공유(0016)는 **육아 기록만** 공유한다. 앨범 사진은 공유하지 않는다 (`0016` 주석, `album_photos` RLS `owner_id = auth.uid()`, `album` 버킷 정책이 본인 폴더로만 제한).
- 따라서 "가족에서 빠지면 사진이 막히는가"가 아니라 **가족을 포함한 다른 회원은 처음부터 사진 링크를 받을 수 없다**를 확인했다.
  - 주인은 서명 링크 발급·열람 가능 / 다른 회원·비로그인은 발급 400 / 다른 회원은 앨범 행 0건 / 남의 폴더 업로드 400.
- 이미 발급한 서명 링크는 **권한 변경으로는 무효가 되지 않고** 파일을 지워야 무효가 된다 (CLAUDE.md 4절과 일치).
  - 1차 실행: 삭제 직후 같은 링크가 200 (CDN 지연으로 판단) → 시험을 "최대 3분, 10초 간격 재확인"으로 고침.
  - 2차 실행: 삭제 즉시 400. 즉 삭제 후 짧은 시간 열릴 수 있음.
- 시험용 사진 1장·행 1개는 끝에 삭제 확인. 기존 사진·기록·가족 상태는 건드리지 않음.
- 챌린지·커뮤니티 사진(`media` 버킷)은 0041 기준 승인글이면 회원 누구나 서명 가능 — 가족 범위와 무관.

## 6. 발견한 문제와 수정

- 앱 코드의 새 오류는 발견하지 못함. 추가한 것은 검증 파일 2개(`tests/album-privacy.spec.mjs`, `tests/deployed-like-click.mjs`)뿐.
- **테스트 환경 메일 차이(수정 아님, 사용자 결정 필요):** 앱 기본 화면은 이메일 **6자리 인증번호** 방식이다. 운영 프로젝트는 사용자 SMTP 와 한국어 번호 메일 템플릿이 있지만, **테스트 프로젝트는 사용자 SMTP 가 없어 메일 템플릿을 바꿀 수 없다**(대시보드 "Set up custom SMTP to edit templates"). 그래서 테스트 사이트에서 인증번호를 요청하면 **번호 대신 Supabase 기본 영어 링크 메일**이 온다. 링크를 누르면 `emailRedirectTo`(테스트 사이트 index.html)로 돌아와 로그인된다. OTP 길이·만료는 테스트도 6자리·10분으로 맞춰 둠. 기본 SMTP 는 시간당 발송 한도가 낮다.
  - 운영과 같은 번호 메일을 테스트에서도 보려면 테스트 프로젝트에 사용자 SMTP 설정이 필요하다 (비밀값이 필요하므로 사용자가 직접).

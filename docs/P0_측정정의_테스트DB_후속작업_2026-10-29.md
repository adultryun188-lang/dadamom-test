# P0 최소 측정 정의와 테스트 DB 후속 작업

## 현재 확인

- 기존 `profiles.signup_from`은 최초 유입 경로, `last_seen`은 마지막 접속 날짜 하나다.
- `last_seen`으로 정확한 7일 내 재행동을 계산할 수 없다. 단순 접속은 글·댓글·기록 완료와 다르다.
- 글·댓글은 기존 데이터로 작성 활동을 일부 집계할 수 있지만 삭제된 활동, 인증 단계 이탈, 가족 초대 열람은 복원할 수 없다.
- 이번 코드 세션에서 스키마를 수정하거나 신규 외부 분석 도구를 연결하지 않았다.

## 집계 정의

| 항목 | 분자 | 분모/기간 |
|---|---|---|
| 첫 행동 | 가입 뒤 글·댓글을 처음 완료한 고유 테스트 참여자 | 관찰 대상 가입자. 이메일 계정 생성과 프로필 완료는 별도 표시 |
| 다른 사람 답변 | 본인·운영자·시드 제외 댓글이 붙은 질문 | 질문 수. 운영자 답변은 별도 집계 |
| 7일 내 재행동 | 가입 이후 다른 한국 날짜이며 가입 시각+7일 이내 의미 있는 행동을 완료한 사람 | 7일 관찰이 끝난 가입자만 포함 |
| 비경품 활동 | 일반 글·댓글·개인 기록 완료 | 챌린지 응원·투표와 분리 |
| 가족 참여 | 초대 뒤 열람·권한 확인·반응 완료를 단계별로 구분 | 유효 초대와 참여자. 단순 링크 생성은 열람으로 세지 않음 |

## 별도 DB 세션 전달 범위

최신 staging의 AGENTS.md·CLAUDE.md·최신 인수인계를 읽고 **테스트 DB `srxdtddrtnhtlbbviyvs`만** 사용한다. 운영 연결·회원 목록 조회·기존 데이터 백필은 금지한다.

1. 현재 테이블·권한·사용자 삭제 정책을 대조한다. 기존 기록에서 계산 가능한 항목과 이벤트가 필요한 항목을 분리한다.
2. 이벤트가 꼭 필요한 최소 항목만 설계한다. 이름 예시는 `post_completed`, `comment_completed`, `record_completed`다. 가족 반응 기능이 없는 상태에서 완료 이벤트를 만들어 내지 않는다.
3. 로그인 이용자는 본인 이벤트만 추가하도록 RLS를 설계한다. 일반 이용자의 타인 이벤트 조회·수정·삭제와 anon 기록은 차단한다. 집계 권한을 앱 공개 클라이언트에 열지 않는다.
4. 본문·사진 URL·이메일·아이 이름/생일·초대 코드·서명 URL은 저장하지 않는다. 행위 시각은 서버 기준, 중복 방지는 행위 ID와 이벤트 종류의 제약으로 처리한다. 집계에 필요 없는 원본 자료 ID는 수집하지 않는다.
5. 가상/운영자 제외는 서버에서 신뢰 가능한 역할 및 사전 등록한 테스트 참여 범위로 결정한다. 클라이언트가 보낸 `is_test`만 신뢰하지 않는다.
6. 보유 기간·탈퇴 시 삭제·기존 정책의 수집 범위를 정하고 문서와 맞춘다. 새 수집이 필요하면 이를 명시한다.
7. 최신 마지막 번호 다음의 마이그레이션, 트랜잭션 리허설, 허용/타인/anon/중복/탈퇴 검증, 역방향 절차를 준비한다.
8. DB 준비 뒤 코드 세션에서 성공한 행위에만 연결한다. 이벤트 저장 실패가 글·댓글 성공을 실패로 바꾸거나 중복 작성하게 하지 않는다.

이는 실행 가능한 마이그레이션 자체가 아니라 다음 DB 세션의 설계·검증 범위다. 이벤트 연결 및 정확한 7일 재행동 측정은 아직 완료되지 않았다.

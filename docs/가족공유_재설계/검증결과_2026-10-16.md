## 수정한 문제

1. 테스트가 성장 화면에서 MY의 가족 버튼을 찾았고, 관찰기 초기화가 너무 빨라 토스트를 놓쳤다.
   화면 위치와 초기화를 수정하고, 고정 대기 대신 실제 상태를 기다리게 했다.
2. 전송 실패 뒤 서버의 예전 값이 미전송 접종 해제를 덮어썼다. outbox의 같은 키는 수신 적용에서 보호한다.
3. 같은 기록을 연속 수정하면 저장 요청이 병렬로 나갔다. 계정·가족별 한 번에 하나씩 순서대로 보내고,
   이전 요청 중 새로 생긴 수정은 다음 요청으로 보낸다.
4. 조회 중 새로 저장을 마친 수정도 예전 조회 응답에 덮일 수 있어, 조회 시작 이후 수정한 키를 보호한다.
5. 수신 1,000행 제한으로 더 많은 기록을 빠뜨렸다. 시각·종류·id를 함께 정렬한 500행 단위 연속 조회로 교체했다.
6. 계정 전환 후 옛 요청이 현재 상태를 건드리지 않도록 계정 id와 상태 객체를 확인한다.

## 정리·재실행

- 테스트는 `finally`에서 브라우저를 닫고 두 테스트 계정을 `leave_family` 및 `family_share=false`로 정리한다.
- API 테스트도 모든 테스트 계정을 가족에서 내보낸다. 두 스크립트는 같은 계정을 사용하므로 순서대로 실행한다.
- 대량 시험 데이터는 해당 임시 가족에만 넣고 마지막 구성원이 나가면 가족과 함께 삭제된다.
- 시작 전부터 있던 미커밋 파일은 보존하고 이번 변경만 커밋한다.
- 시작 시 미커밋 파일 때문에 `pull --rebase`는 실행되지 않았다. `fetch`로 확인한 결과 HEAD와 원격 staging은 동일했다.

## 1. 왜 다시 만들었나

옛 구현(`index.html` 3886~3991행)은 다음 문제로 막혀 있었습니다.

1. 6자리 코드(`Math.random`)만 알면 계정 확인 없이 기록 전체와 닉네임·지역을 읽음
2. 저장할 때마다 기록 전체를 덮어써서 두 사람이 기록하면 한쪽이 사라짐
3. 저장 실패를 삼킴 (`.then(function(){})`, `catch(e){}`)
4. `families` 표에 소유자가 없어 탈퇴해도 안 지워짐

### 2-2. 서버 쪽 (이미 있음)

| 이름 | 용도 | 돌려주는 것 / 오류 message |
|---|---|---|
| `rpc my_family()` | 내 가족 | `null` 또는 `{family_id, is_owner, invite_code, invite_expires_at, members:[{user_id,nickname,is_me,is_owner,joined_at}]}` |
| `rpc create_family()` | 만들기 | `{family_id, invite_code, invite_expires_at}` / `consent_required` `already_in_family` |
| `rpc join_family({p_code})` | 참여 (대소문자·하이픈 무시) | `{family_id}` / `consent_required` `already_in_family` `invalid_code` `family_full` |
| `rpc new_family_invite()` | 새 코드 (이전 코드 무효) | `{invite_code, invite_expires_at}` / `not_in_family` |
| `rpc leave_family()` | 나가기 | `{ok}` |
| `rpc remove_family_member({p_user})` | 빼기 (만든 사람만) | `{ok}` / `not_owner` `use_leave` `not_member` |
| 표 `family_records` | 기록 | 열: `family_id, kind('care'\|'growth'\|'vaccine'), rid, body(jsonb), deleted, updated_at, updated_by` |

- `updated_at`·`updated_by` 는 **서버가 찍습니다.** 보내도 무시됩니다.
- 삭제는 행을 지우지 않고 `deleted: true` 로 upsert 합니다 (DELETE 권한 없음).
- 동의는 만들기·참여 **전에** `consent_records` 에 `{kind:'family_share', granted:true}` 를 넣어야 합니다. 서버가 가장 최근 값을 확인합니다.

### 2-3. 기록 ↔ 행 대응

| 앱 상태 | kind | rid | body |
|---|---|---|---|
| `state.careLog[]` `{id,type,ts}` | `care` | `id` (`c…`) | `{type, ts}` |
| `state.growthRecords[]` `{id,ts,height,weight}` | `growth` | `id` (`g…`) | `{ts, height, weight}` |
| `state.vaccines{vid: bool}` | `vaccine` | `vid` | `true`/`false` |

### 2-4. 동기화 규칙
1. **시작·참여 직후**: 이 기기의 기록 전부를 upsert (합집합). 그 뒤 전체 내려받기.
2. **앱 열 때·로그인 직후·가족 화면 열 때**: `my_family()` → null 이면 가족 상태를 지우고 "가족 공유에서 빠졌어요".
   있으면 `family_records?family_id=eq.X&updated_at=gte.<커서-2분>&order=updated_at` 로 받아 적용
   (`deleted` 면 로컬에서 제거, 아니면 id 기준으로 넣거나 교체). 커서는 받은 것 중 최대 `updated_at`.
   2분 겹치는 이유: 같은 시각에 커밋된 행을 놓치지 않게. upsert 라 중복 적용해도 같습니다.
3. **기록을 남기거나 지울 때마다**: 그 한 건을 upsert. 보내기 전에 기기 보관함(outbox)에 넣고, 성공하면 뺍니다.
   실패하면 남겨 두고 다음 동기화 때 다시 보냅니다. **실패는 토스트로 보이게** (CLAUDE.md 4절).
4. upsert 는 `Prefer: resolution=merge-duplicates` · **`.select()` 를 붙이지 않습니다** (return=minimal).
5. **나가기**: `leave_family()` + `consent_records {family_share, granted:false}`. 로컬 기록은 그대로 둡니다.

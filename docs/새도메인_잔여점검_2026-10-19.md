### 2. 일반 고객용 인증 메일 — 이메일 가입 공개 전

- 운영 Authentication > Emails > SMTP Settings의 Enable custom SMTP 스위치가 **꺼짐**.
- 가입 인증 메일은 기본 템플릿이며 ConfirmationURL 변수를 사용한다. 옛 GitHub URL을 직접 박아둔 가입 메일 템플릿은 보이지 않았다. 실제 메일 수신·클릭은 시험하지 않았다.
- Supabase 기본 발송 서비스는 프로젝트 팀 소속 주소만 대상으로 하며, 공식 문서상 현재 제한은 시간당 2통이다. Google·Kakao 로그인 성공과 일반 고객 이메일 가입 가능 여부는 별개다.
- 도메인 전환 때문에 새로 생긴 문제는 아니지만, 이메일 가입·매직링크를 고객에게 제공하기 전 해결해야 한다.
- 다음 작업: 발송 서비스와 발신 주소 선택 → 해당 서비스가 요구하는 DNS 인증(SPF/DKIM 등) → custom SMTP 연결 → 별도 테스트 환경에서 실제 메일 수신/복귀 검증. 계정 생성·키 입력·비용 동의는 별도 승인 범위다. 인증 비활성화나 팀 초대로 우회하지 않는다.
- 근거: [Supabase 공식 SMTP 안내](https://supabase.com/docs/guides/auth/auth-smtp).

- 운영 코드의 육아 기록은 출처별 localStorage에 저장된다. github.io와 dadamom.co.kr의 저장 공간은 다르다. 기존 기록을 읽거나 복사하지 않았다.

### 4. 공유 미리보기·검색 기본 설정

- 라이브 index.html 및 community.html의 og:url과 og:image가 **모두 기존 GitHub 주소**다. 이미지는 새 도메인에서도 200이므로 당장 이미지가 깨진 것으로 판정하지 않는다. 링크·미리보기의 기준 주소 정리가 필요하다.

- 다음 작업: 운영/테스트 값을 분리해 OG·대표 URL을 새 도메인으로 생성하고 검색용 파일 준비 → Search Console·네이버 서치어드바이저 등록 상태 확인 및 새 도메인 제출 → 공유 서비스 캐시 갱신·실기기 미리보기 확인.
- 글별 주소는 #/p/...이고 OG는 정적 공통 값이다. **도메인 문자열 교체만으로 글별 검색·미리보기가 해결되지는 않는다.** 공개 글만 대상으로 별도 URL/렌더링 설계가 필요한 후속 과제다. sitemap에 해시 글 주소를 무작정 나열하지 않는다.

### 6. PWA 식별자·캐시

- 라이브 manifest의 start_url=./index.html, scope=./은 새 루트에서 해석 가능하다. 아이콘 파일도 모두 정상이다.
- id=/dadamom-app/ 값이 남아 있지만 **id는 실제로 열어야 하는 페이지가 아니므로 그 자체로 설치 오류라고 단정하지 않는다.** 식별자를 바꾸면 별도 앱으로 인식될 수 있으므로 설치 이전 정책을 정한 뒤 판단한다.

- 근거: [MDN manifest id](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/id).

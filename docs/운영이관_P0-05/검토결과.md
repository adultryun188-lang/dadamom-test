### ⚠️ 한 가지 틈 (배포 막는 건 아님)

`handleApplySubmit` 이 `if(appId)` 로 PII insert 를 감쌉니다. `appId = newUuid()` 인데
`newUuid()` 는 `window.crypto` 가 아예 없으면 `null` 을 돌려줍니다(1363~1373줄).

그 경우 **신청 행은 들어가고 PII insert 는 건너뛰어집니다.** 사용자에게는
"접수됐어요" 로 보이는데 **연락처·주소가 아무 데도 안 남습니다** — 당첨돼도
보낼 수가 없습니다.

HTTPS 운영 환경의 현대 브라우저에서는 `crypto.randomUUID` 가 항상 있어 사실상
발생하지 않습니다. 다만 구형 웹뷰 등에서 조용히 실패하는 길이 열려 있습니다.
`appId` 가 없으면 신청 자체를 막고 안내하는 쪽이 안전합니다. 별도 건으로 둡니다.

## 단계 A 파일 — 손작업 없이 붙여넣기만

지시서는 "`0006` 의 `drop column` 두 줄을 주석 처리하고 실행" 하라고 했습니다.
운영 SQL Editor 에서 손으로 편집하는 게 이 작업의 가장 위험한 지점이라
미리 처리해 두었습니다.

| 파일 | 용도 | `begin`/`commit`/`rollback` |
|---|---|---|
| `0_사전점검.sql` | 3절 읽기 전용 점검 (+ 컬럼 존재 확인 추가) | — |
| `A_리허설.sql` | `0006`(수정)+`0007`+`0008` 리허설 | 1 / 0 / 1 |
| `A_적용.sql` | 같은 내용 실제 적용 + 확인 표 4개 | 1 / 1 / 0 |
| `C_컬럼삭제.sql` | 단계 C (B 배포 확인 뒤) | 1 / 1 / 0 |

- 두 A 파일에 **살아있는 `drop column` 이 0줄**임을 확인했습니다
  (주석으로만 남아 73~74줄에 보입니다)
- 셋을 한 트랜잭션에 넣은 이유: `0007` 은 `0006` 이 만든 함수·표를 고치고,
  `0008` 은 `0006` 의 컬럼에 권한을 걸므로 따로 리허설하면 '없음' 으로 실패합니다
- 확인 표에 **[표 4] 를 추가**했습니다 — `contact`/`address` 컬럼이 **아직 1개씩
  살아있는지** 봅니다. 0 이면 실수로 지워진 것이고, 코드 배포 전까지 체험단
  신청이 전부 실패합니다

## 0. 무엇이 왜 깨졌나

첫 화면에 로그인 폼을 심으면서 `#auth-email` / `#auth-password` / `#auth-hint` /
`#auth-password-submit` 이 **문서에 두 벌** 존재하게 됐습니다. 첫 화면(`#onboarding-auth`)과
모달(`#modal-card`). 첫 화면은 숨겨져도 **DOM 에는 그대로 남습니다.**

`document.getElementById` 는 문서에서 **먼저 나오는 쪽**을 돌려줍니다. 첫 화면이
모달보다 앞에 있으므로, 커뮤니티 배너에서 모달을 열어 입력해도
`handlePasswordAuth()` 는 **숨겨진 빈 칸**을 읽고

```js
if(!email || password.length < 6) return;   // 아무 일도 안 하고 끝
```

에서 조용히 끝납니다. **비로그인 사용자가 커뮤니티에서 로그인 버튼을 눌러도 아무 반응이
없습니다.** 첫 화면에서의 로그인은 정상이라 눈에 안 띄었습니다.

실측(테스트 환경, 고치기 전):

```
#auth-email 개수: 2
getElementById 가 돌려주는 것: #screen-onboarding > #onboarding-auth > #auth-email  ← 숨겨진 쪽
모달 쪽 값: ""   (사용자가 친 값은 숨겨진 쪽에 들어가 있음)
```

②는 `refreshAuthForms()` 가 `innerHTML` 로 폼을 통째로 갈아끼우는데 `value=` 를
안 내보내고 값을 어디에도 보관하지 않아서 생깁니다.

**고친 방식:** ① 로그인 폼은 문서에 **언제나 한 벌만** 존재하게 한다.
② 교체 전에 값을 변수에 들고 있다가 교체 후 되살린다. (비밀번호 칸은 '이메일 링크'
보기에서 아예 사라지므로 DOM 이 아니라 변수여야 왕복해도 살아남습니다.)

## 2. 넣을 것 5군데

각 "찾기" 는 파일에 **정확히 1번**만 나와야 합니다. 아니면 멈추고 보고하세요.

### [1] 로그인 성공 시 임시 보관값 비우기

찾기:
```
          if(event === 'SIGNED_IN'){ showToast('로그인됐어요'); }
```
바꾸기:
```
          if(event === 'SIGNED_IN'){ clearAuthDraft(); showToast('로그인됐어요'); }
```

### [2] 입력 보관 함수 3개 + `refreshAuthForms` 수정

찾기:
```
  // 로그인 폼은 모달과 첫 화면 두 군데에 있을 수 있다.
  // 탭(로그인/회원가입)이나 방식(비밀번호/이메일 링크)을 바꾸면 둘 다 다시 그린다.
  function refreshAuthForms(){
    var card = document.getElementById('modal-card');
    if(card && card.innerHTML) card.innerHTML = authModalHtml();
    var inline = document.getElementById('onboarding-auth');
    if(inline && inline.offsetParent !== null) inline.innerHTML = authBodyHtml();
  }
```
바꾸기:
```
  // 폼을 다시 그리면 input 이 통째로 교체되므로, 치던 값이 사라진다.
  // 비밀번호 칸은 '이메일 링크' 보기에서는 아예 없어지므로 DOM 이 아니라
  // 여기에 들고 있어야 왕복해도 살아남는다.
  var authDraft = { email: '', password: '' };

  function captureAuthDraft(){
    var e = document.getElementById('auth-email');
    var p = document.getElementById('auth-password');
    if(e) authDraft.email = e.value;
    if(p) authDraft.password = p.value;
  }

  function restoreAuthDraft(){
    var e = document.getElementById('auth-email');
    var p = document.getElementById('auth-password');
    // input 이벤트를 다시 쏴야 제출 버튼의 disabled 가 맞춰진다.
    if(e && authDraft.email){ e.value = authDraft.email; e.dispatchEvent(new Event('input', { bubbles:true })); }
    if(p && authDraft.password){ p.value = authDraft.password; p.dispatchEvent(new Event('input', { bubbles:true })); }
  }

  function clearAuthDraft(){ authDraft = { email: '', password: '' }; }

  // 로그인 폼은 모달과 첫 화면 두 군데에 있을 수 있다.
  // 탭(로그인/회원가입)이나 방식(비밀번호/이메일 링크)을 바꾸면 둘 다 다시 그린다.
  function refreshAuthForms(){
    captureAuthDraft();
    var card = document.getElementById('modal-card');
    if(card && card.innerHTML) card.innerHTML = authModalHtml();
    var inline = document.getElementById('onboarding-auth');
    if(inline && inline.offsetParent !== null) inline.innerHTML = authBodyHtml();
    restoreAuthDraft();
  }
```

### [3] `renderOnboarding` — 화면 밖이면 폼을 비운다 (**①의 핵심**)

찾기:
```
    if(needLogin){
      // 입력 중인 내용을 지우지 않도록, 비어 있을 때만 그린다
      var inline = document.getElementById('onboarding-auth');
      if(inline && !inline.innerHTML) inline.innerHTML = authBodyHtml();
      return;
    }
```
바꾸기:
```
    if(needLogin){
      var inline = document.getElementById('onboarding-auth');
      var onScreen = welcome && welcome.offsetParent !== null;
      if(inline){
        // 첫 화면이 안 보이는데 폼을 남겨두면 모달의 로그인 폼과 id 가 겹친다.
        // getElementById 는 먼저 나오는 쪽(첫 화면)을 돌려주므로, 모달에 입력해도
        // 빈 값을 읽어 제출이 조용히 무시된다. 그래서 화면 밖이면 비워 둔다.
        if(!onScreen) inline.innerHTML = '';
        // 입력 중인 내용을 지우지 않도록, 비어 있을 때만 그린다
        else if(!inline.innerHTML) inline.innerHTML = authBodyHtml();
      }
      return;
    }
```

> `welcome` 은 같은 함수 위쪽에서 이미
> `var welcome = document.getElementById('onboarding-welcome');` 로 잡아둔 변수입니다.
> 새로 선언하지 마세요.

### [4] `openModal` — 열 때 첫 화면 폼을 비운다

찾기:
```
  function openModal(html){
    _modalLastFocus = document.activeElement;
    document.getElementById('modal-card').innerHTML = html;
```
바꾸기:
```
  function openModal(html){
    _modalLastFocus = document.activeElement;
    // 모달이 열려 있는 동안에는 첫 화면의 로그인 폼을 비운다 (id 중복 방지)
    var inlineAuth = document.getElementById('onboarding-auth');
    if(inlineAuth) inlineAuth.innerHTML = '';
    document.getElementById('modal-card').innerHTML = html;
```

### [5] `closeModal` — 닫으면 비우고 첫 화면을 되살린다

찾기:
```
  function closeModal(){
    document.getElementById('modal-backdrop').hidden = true;
    document.getElementById('modal-card').innerHTML = '';
    if(_modalLastFocus && typeof _modalLastFocus.focus === 'function'){ _modalLastFocus.focus(); }
```
바꾸기:
```
  function closeModal(){
    document.getElementById('modal-backdrop').hidden = true;
    document.getElementById('modal-card').innerHTML = '';
    clearAuthDraft();   // 모달을 닫으면 치던 비밀번호를 메모리에 남기지 않는다
    renderOnboarding(); // 첫 화면이 보이는 중이었다면 로그인 폼을 다시 채운다
    if(_modalLastFocus && typeof _modalLastFocus.focus === 'function'){ _modalLastFocus.focus(); }
```

## 4. 배포 후 확인 — ①이 핵심입니다

로그아웃 상태(시크릿 창 권장)로:

- [ ] 첫 화면 → 이메일·비밀번호 폼이 바로 뜬다
- [ ] 이메일·비밀번호를 치고 **로그인/회원가입 탭을 바꿔도 값이 남아 있다**
- [ ] "이메일 링크로 로그인하기" → 되돌아와도 **비밀번호까지** 남아 있다
- [ ] **"로그인 없이 커뮤니티 둘러보기" → 배너의 "로그인하고 시작하기" → 모달에
      이메일·비밀번호를 치고 제출 → 반응이 있다** (틀린 비밀번호면
      "로그인 실패: …" 가 폼 아래에 뜬다). **지금 운영에서는 아무 반응이 없습니다.**
- [ ] 모달을 닫고 첫 화면으로 돌아가면 폼이 다시 보이고 **비어 있다**
- [ ] 콘솔에서 `document.querySelectorAll('#auth-email').length` 가 **어느 상태에서도 1 이하**
- [ ] 콘솔 에러 0

테스트 환경에서 위 전부 확인했습니다 (`a3bae38f`).

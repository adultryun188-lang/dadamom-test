### ❌ 7절의 "입력 내용이 안 지워진다" 는 성립하지 않습니다

실측: 이메일 칸에 값을 넣고 로그인↔회원가입 탭을 바꾸면 `value` 가 `""` 가 됩니다.

코드로도 확정됩니다.

- `authBodyHtml()` 은 `<input type="email" id="auth-email" placeholder="…">` 를
  **`value=` 속성 없이** 출력합니다 (`grep -c 'id="auth-email" value='` → 0)
- 탭·토글 핸들러는 `authMode`/`authView` 만 바꾸고 `refreshAuthForms()` 를 부릅니다
- `refreshAuthForms()` 는 `innerHTML = authBodyHtml()` 로 **입력을 파괴**합니다
- `input` 이벤트 핸들러는 제출 버튼의 `disabled` 만 토글하고 값을 보관하지 않습니다

즉 **로그인↔회원가입 탭**과 **이메일링크↔비밀번호 토글** 양쪽에서 이메일·비밀번호가
비워집니다. 해시가 지시서 기대값과 정확히 일치하므로 **제 빌드 실수가 아니라
명세된 코드 자체의 동작**입니다.

영향: 사용자가 이메일을 다시 입력해야 합니다. 보안·데이터 문제는 아니고
배포를 되돌릴 사유도 아닙니다.

고치는 방법 (운영 변경이라 승인 대기):

```js
  function refreshAuthForms(){
    // 다시 그리기 전에 입력값을 들고 있는다. innerHTML 교체가 input 을 파괴한다.
    var keep = {};
    ['auth-email','auth-password'].forEach(function(id){
      var el = document.getElementById(id);
      if(el) keep[id] = el.value;
    });
    var card = document.getElementById('modal-card');
    if(card && card.innerHTML) card.innerHTML = authModalHtml();
    var inline = document.getElementById('onboarding-auth');
    if(inline && inline.offsetParent !== null) inline.innerHTML = authBodyHtml();
    Object.keys(keep).forEach(function(id){
      var el = document.getElementById(id);
      if(el) el.value = keep[id];
    });
    // 값을 되살렸으니 제출 버튼 상태도 다시 맞춘다
    var e2 = document.getElementById('auth-email');
    if(e2) e2.dispatchEvent(new Event('input', {bubbles:true}));
  }
```

## 0. 왜 클라우드 세션이 직접 못 하는가

운영 `index.html` 을 만드는 행위 자체가 세션 안전장치에 **운영 배포로 분류되어 차단**됐습니다.
대신 **클라우드 세션이 결과물을 미리 만들어서 검증까지 끝내 놨습니다.**
아래 3절대로 따라오시면 **바이트 단위로 동일한 파일**이 나옵니다.
그 해시가 안 맞으면 어딘가 다른 겁니다 — 멈추고 보고하세요.

## 5. DB — `0011` (코드 배포보다 **먼저**)

운영 Supabase(`hjqchbpxwviengdzvado`) SQL Editor.
**반드시 리허설 먼저** (`begin; … rollback;`), 결과 확인 후 `begin; … commit;`.

파일: 테스트 저장소의 `supabase/migrations/0011_edit_own_content.sql` **그대로**.
환경에 의존하는 내용이 없습니다. 함수 2개를 추가할 뿐이고 기존 표·정책은 건드리지 않습니다.

- `edit_my_post(uuid, text)` — 본인 글 본문만, 2000자, 수정하면 `status='pending'`
- `edit_my_entry(uuid, text)` — 본인 참가작 note 만, 500자, 동일

적용 후:
```sql
select p.proname, pg_get_function_identity_arguments(p.oid) as 인자
  from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname='public' and p.proname in ('edit_my_post','edit_my_entry');
-- 2행

select p.proname, r.rolname, has_function_privilege(r.rolname, p.oid, 'execute') as 실행가능
  from pg_proc p join pg_namespace n on n.oid=p.pronamespace,
       (values ('anon'),('authenticated')) as r(rolname)
 where n.nspname='public' and p.proname in ('edit_my_post','edit_my_entry');
-- anon = false, authenticated = true 여야 합니다
```

**`0011` 을 먼저 올려도 사용자에게는 아무 변화가 없습니다** (아직 부르는 코드가 없음).
반대로 코드를 먼저 올리면 '수정' 버튼이 생겼는데 함수가 없어서 실패합니다.

## 7. 배포 후 확인

- [ ] **로그아웃 상태로 앱 열기 → 이메일·비밀번호 폼이 바로 뜬다.**
      카카오·구글 버튼도 그대로 (운영은 소셜 로그인이 켜져 있습니다)
- [ ] 로그인 ↔ 회원가입 탭 전환 (버튼 글자가 "회원가입하기" 로 바뀜)
- [ ] "이메일 링크로 로그인하기" ↔ "비밀번호로 로그인·회원가입" 왕복
- [ ] 이메일 치다가 탭을 바꿔도 **입력한 내용이 안 지워진다**
- [ ] "로그인 없이 커뮤니티 둘러보기" 정상
- [ ] 커뮤니티 배너의 **모달 로그인**도 머리말·탭·토글 정상
- [ ] 프로필 있는 계정 로그인 → 온보딩 없이 바로 홈
- [ ] 프로필 없는 계정 로그인 → 단계·지역 1회 입력 → 저장 → 홈
- [ ] 내 글에 **삭제·수정** 버튼, 남의 글에는 **신고**
- [ ] 글 수정 → "검수 중" 배지, 비로그인 창에서는 안 보임
- [ ] 글 삭제 → **사진 파일까지 지워짐** (Storage 에서 확인)
- [ ] 다른 기기(시크릿 창)에서 로그인 → 내 글에 삭제·수정이 뜬다
- [ ] 좋아요·응원 숫자가 **예전처럼 동작** (P0-03 은 안 올라갔습니다)
- [ ] MY 화면 **맨 아래**에 회원 탈퇴
- [ ] 콘솔 에러 0

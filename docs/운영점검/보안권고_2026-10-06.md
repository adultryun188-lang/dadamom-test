# 운영 보안 권고 실측 — 2026-10-06

Supabase MCP 의 `get_advisors`(security) 를 운영 프로젝트
(`hjqchbpxwviengdzvado`)에 돌려 받은 결과입니다. **추측이 아니라 실측입니다.**

> `execute_sql` · `list_tables` 는 세션 권한 분류기가 `Production Reads` 로
> 차단합니다(운영·테스트 둘 다). `list_projects` · `get_advisors` 만 통과했습니다.
> 그래서 아래는 권고 조회로 알 수 있는 범위까지입니다.

---

## 1. ⚠️ 비로그인이 아직 카운터를 조작할 수 있습니다

```
increment_votes(p_id uuid, delta integer)
increment_likes(p_id uuid, delta integer)
increment_comments(p_id uuid)
→ 전부 anon 역할로 /rest/v1/rpc/ 호출 가능 (SECURITY DEFINER)
```

CLAUDE.md 4절 지뢰 목록의 그 건입니다 —
*"0002 만 적용해도 숫자 조작은 막히지 않습니다… 2026-09-30 실측: votes 11 → 18"*.

`0005_reactions.sql` 이 이 함수들을 `drop` 으로 정리하는데 **운영에 적용돼
있지 않습니다**(P0-03 미이관). 그래서 지금 운영에서 누구나 좋아요·응원 숫자를
올릴 수 있습니다. **예상된 결과이지만 운영에서 확인된 것은 처음입니다.**

→ P0-03(`0002`+`0005`) 이관이 열려 있는 한 이 구멍은 계속 열려 있습니다.
   `0002` 만 올려도 닫히지 않습니다. `0005` 가 같이 가야 합니다.

## 2. ⚠️ 백업 표에 PII 평문 사본이 남아 있을 수 있습니다

`backup_private` 스키마에 2026-09-28 백업이 있습니다:

- `backup_private.benefit_applications_20260928`
- `backup_private.challenge_entries_20260928`
- `backup_private.community_posts_20260928`

P0-05(`0006`+`0008`)는 연락처·주소를 `benefit_applications_pii` 로 분리하고
90일 뒤 파기하도록 만들었습니다. 그런데 **백업 표에 같은 값의 평문 사본이
있으면 파기가 의미 없어집니다.** 개인정보 처리방침의 보관기간과도 어긋납니다.

컬럼을 확인하려 했으나 `list_tables` 가 차단돼 못 봤습니다.
→ `backup_private.benefit_applications_20260928` 에 `contact`·`address` 가
  있는지 확인하고, 있으면 그 두 컬럼을 지우거나 표 자체를 정리해야 합니다.

세 표 모두 RLS 는 켜져 있고 정책이 없어 API 로는 안 읽힙니다(fail-closed).
`service_role` 과 대시보드로는 보입니다.

## 3. `search_path` 가 고정되지 않은 함수 7개

```
mask_contact · mask_address · is_admin · increment_votes
increment_likes · increment_comments · touch_updated_at
```

`is_admin` 은 SECURITY DEFINER 인데 `search_path` 가 가변입니다 —
권한 상승 경로가 됩니다. `mask_contact`·`mask_address` 는 `0006` 이 만든
것인데 `0007`(0006 의 구멍 막기)이 이 부분은 다루지 않았습니다.

고치는 방법: 각 함수에 `set search_path = public` 을 붙입니다.
`increment_*` 셋은 `0005` 가 어차피 `drop` 하므로 P0-03 이관으로 함께 해소됩니다.

## 4. `admin_emails` · `families` — RLS on, 정책 없음 (INFO)

`admin_emails` 는 **의도된 것**입니다 (`0001` 주석: "정책 없음 = 클라이언트에서
직접 읽을 수 없음. is_admin() 함수로만 조회된다"). `families` 는 쓰이지 않는
표로 보입니다 — 확인 후 정리 대상.

## 5. 유출 비밀번호 보호가 꺼져 있습니다

Supabase Auth 설정에서 켜면 HaveIBeenPwned 대조가 들어갑니다.
코드 변경 없이 설정 한 번입니다.
https://supabase.com/docs/guides/auth/password-security

## P0-04 질문은 이걸로 안 풀립니다

다른 세션이 본 *"Clients can list all files in this bucket — A broad SELECT
policy on storage.objects"* 는 **Storage 화면 경고**이고 DB 린터 항목이
아닙니다. 권고 목록에 안 나온 것이 "없다" 는 뜻이 아닙니다.

확인에는 `pg_policies` 조회가 필요하고 그건 `execute_sql` 입니다 —
현재 차단 상태입니다. `docs/P0-04_검토/08_storage정책_진단.sql` 을 돌리면 됩니다.

```sql

  (select count(*) from pg_constraint where conname like '%consent_records%kind%'
     and pg_get_constraintdef(oid) like '%signup_terms%') > 0          as 가입동의종류_허용,
  (select count(*) from information_schema.columns where table_schema='public'
     and table_name='benefit_applications' and column_name in ('contact','address')) as 남은개인정보컬럼,
  (select count(*) from public.benefit_applications)                   as 신청수,
  (select count(*) from public.outings)                                as 나들이행수,
  (select count(*) from information_schema.columns where table_schema='backup_private'
     and table_name='benefit_applications_20260928'
     and column_name in ('contact','address'))                         as 백업표_개인정보컬럼;
select id, category, region, title, place from public.outings order by title;
```

## 5. 작업 규칙 (반드시)

1. **운영(`dadamom-app` 저장소, Supabase `hjqchbpxwviengdzvado`)은 대표 승인 없이 수정·배포하지 않는다.**
2. 모든 변경은 **테스트 먼저**: `dadamom-test` 의 `staging` 브랜치 → 테스트 DB `srxdtddrtnhtlbbviyvs` → 배포본에서 직접 눌러 확인 → 운영 이관.
3. **DB 먼저, 코드 나중.** 운영 SQL 은 `begin; … rollback;` 리허설 후 적용. 사람이 숫자를 읽어 판단하게 만들지 말고 **SQL 이 조건 불만족 시 스스로 `raise exception`** 하게 쓴다 (SQL Editor 는 마지막 결과만 보여줌).
4. 운영 키·`service_role`·`sb_secret_*` 를 코드나 저장소에 넣지 않는다 (배포 워크플로가 빌드 실패시킴).
5. `main` 직접 커밋 금지(테스트 저장소). 커밋 메시지는 한국어로 무엇을 왜.
6. 실제 계정 생성·실데이터 삭제는 하지 않는다. 테스트 계정 비밀번호는 `dadamom-test-1234` (`admin@`·`momA@`·`momB@`·`dadC@dadamom.test`).
7. 운영 이관 시 **단계별 SHA-256 해시로 검증**. 이관 지시서는 "목표 해시 + 손작업 위치 + 확인 항목" 을 적는다.
8. 사용자 커뮤니케이션: **묻지 말고 끝까지 하고 결과만 보고.** 표·번호로 짧게. 묻는 건 운영에 닿는 것, 되돌릴 수 없는 것, 제품 결정 셋뿐.

## 7. 밟은 지뢰 — 다시 밟지 말 것

| 지뢰 | 결과 | 대처 |
|---|---|---|
| 같은 id 의 폼이 두 곳(첫 화면 + 모달)에 있음 | `getElementById` 가 숨은 쪽을 집어 로그인이 조용히 실패 | 인증 폼은 DOM 에 하나만. 모달 열 때 첫 화면 폼 비움 |
| 탭 전환 시 폼을 다시 그림 | 입력값 유실 | `authDraft` 객체에 값 보관, `value=` 로 다시 그림, 그린 뒤 `syncAuthButtons()` |
| 함수 권한을 `from anon` 만 회수 | 안 막힘 (PUBLIC 상속) | `revoke … from public, anon` 또는 drop |
| RPC 파라미터 이름 틀림 + `.catch(()=>{})` | 좋아요가 한 번도 저장 안 됨 | RPC 실패는 반드시 보이게 |
| PostgREST PATCH/DELETE | RLS 가 0행으로 막아도 204 | 값을 다시 읽어 확인 |
| `INSERT … RETURNING` + pending 기본값 | 42501 | `.select()` 빼고 uuid 클라이언트 생성 |
| RLS 정책 안에서 다른 표 직접 참조 | anon permission denied | security definer 함수로 감쌈 |
| `auth.users` SQL 생성 시 토큰 컬럼 NULL | 로그인 500 | 빈 문자열 `''` |
| 서명 URL | 버킷 private 로 바꿔도 살아 있음 | 파일을 옮기거나 지워야 무효화 |
| `storage.objects` SQL 삭제 | 트리거가 막음 | Storage API 로 |
| 서비스워커 + `max-age` 캐시 | 옛 `env.js`/`index.html` 이 보임 | SW unregister, `caches.delete`, `fetch(…,{cache:'reload'})` |
| JS 문자열 길이 ≠ UTF-8 바이트 | 바이트 수 검증 틀림 (한글 3바이트) | 바이트는 `TextEncoder` 로 |
| `grep -c` | 줄 수지 출현 횟수가 아님 | 기대값도 같은 명령으로 계산 |
| `OUTINGS` 이모지 | 파일에 `\ud83c…` 이스케이프 문자열로 들어 있음 | 찾을 문자열은 파일에서 직접 잘라 씀 |
| Supabase SQL Editor | 마지막 문장 결과만 보임 | DO 블록 + `raise exception` 가드 |
| 운영/테스트 프로젝트 혼동 | 엉뚱한 DB 에 SQL 실행 | SQL 첫 줄에 프로젝트 가드 (예: 운영엔 `entry_votes` 없음) |
| 체험단 id 생성 실패 | 접수는 됐는데 PII 연결 안 됨 | id 없으면 접수 차단 (적용됨) |

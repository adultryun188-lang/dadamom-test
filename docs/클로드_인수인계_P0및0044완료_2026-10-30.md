## 7. 0044 현재 원격 적용 상태 — 중복 적용 금지

**0044는 2026-10-29 원격 테스트 DB에 적용 완료됐다.** 10월 30일 현재 상태와 검증을 재확인했다. 어제 사용량 제한으로 세션이 중단됐으나 적용 자체가 실패한 것은 아니다.

적용 객체:

- `pilot_activity_cohort(user_id, joined_at, enrolled_at, expires_at)`
- `pilot_activity_days(user_id, activity_day, kind, first_at)`
- `capture_pilot_activity_day()`
- `pilot_post_activity` / `pilot_comment_activity` AFTER INSERT 트리거
- `purge_pilot_activity()`

보존 내용은 참여자 식별 ID·활동일·글/댓글 종류·해당 일의 최초 서버 시각이다. 원본 글 ID·본문·사진·이메일·아이 정보·초대 코드는 측정 표에 담지 않는다.

- 명시적으로 등록된 파일럿만 수집. 일반 회원 자동 등록·과거 자료 백필 없음.
- 수집 기간 최대 30일. 등록 전·만료 후 수집 차단.
- 같은 날 같은 종류 중복 제거.
- 원본 글·댓글을 삭제해도 최소 활동 날짜는 보존.
- 탈퇴/코호트 삭제 시 활동은 cascade 삭제.
- 양 표의 RLS 활성. anon/authenticated의 CRUD와 두 함수 직접 호출 차단.
- 측정 저장 장애는 원본 글 작성을 막지 않고 SQLSTATE만 경고.
- **현재 코호트 0건, 활동 0건. 실제 회원 수집은 켜지지 않았다.**

SQL Editor 적용이므로 `supabase_migrations.schema_migrations`의 0044 행을 임의 삽입하지 않았다. 이력 표에 번호가 없다는 이유만으로 재적용하면 안 된다. 적용 결과 문서와 실제 스키마·함수 해시를 함께 확인한다.

## 8. 원격 검증과 자동 정리 설정

### 검증 결과

- 원격 통합 검증 **36개 통과**.
- 10월 30일 로컬 재검증 **94개 통과**: DB 58 + 최소 입력/CLI 연결 22 + 기존 집계 14.
- 원격 가상 활동에서 추출한 입력의 두 집계 경로 일치도 별도 확인.
- 전용 UUID fixture만 트랜잭션 안에서 만들고 마지막 전체 롤백했다. 기존 계정 삭제 없음.
- 원격 코호트·활동·추출 전용 계정 각 0건, 강제 실패용 함수 없음을 확인했다.
- 기존 실제 회원·알려진 테스트 계정의 개인 기록·기존 가족 동의 이력을 변경하지 않았다.

### 자동 정리 확정 상태

| 항목 | 값 |
|---|---|
| 전용 작업 이름 | `dadamom-pilot-activity-purge-daily` |
| 최종 jobid | `6` |
| 명령 | `select public.purge_pilot_activity()` |
| 활성 | `true` |
| DB cron timezone | GMT |
| cron 표현 | `20 18 * * *` |
| 한국 일정 | 매일 **03:20 KST** |
| 최초 정기 실행 예정 | **2026-10-31 03:20 KST** |

파일럿 코호트의 `enrolled_at <= statement_timestamp() - interval '89 days'`만 정리한다. 정상 일일 실행 간격을 고려해 등록 후 90일 상한을 지키려는 설정이다. 다른 표·기존 cron은 변경하지 않았다. 작업 장애/중단 시 자동 파기가 보장된다고 주장하지 않는다.

실제 cron 구동 검증은 임시 **jobid 5**, 1분 간격에서 `succeeded`를 확인한 것이다. 이 임시 작업은 해제하고 일일 jobid 6을 등록했다. **jobid 5의 성공 이력을 jobid 6의 정기 실행 성공으로 표현하면 안 된다.**

당시 두 표가 비어 있었으므로 cron 반환 `1 row`는 SELECT 결과 1행이며 삭제 1건을 뜻하지 않는다. 실제 정리 대상 경계·cascade·비대상 보존은 별도 원격 fixture로 검증했다.

자동 승인 검토에서 같은 이름의 일정 직접 전환은 거부됐다. 전용 임시 작업만 명시적 해제하고 0건 확인 후 일일 작업을 새로 등록하는 허용된 방식으로 완료했다. 안전장치 우회나 미해결 승인 대기는 없다.

#### 5. 남편 참여 방식

문제를 **설치를 꺼리거나 기록을 자주 하지 않는 사람도 참여할 수 있는가**로 바꾼다. 처음부터 ‘부부 모두 매일 기록’을 목표로 잡지 않는다.

| 참여 유형 | 처음 부탁할 행동 | 이후 연결 |
|---|---|---|
| 보내주면 보는 사람 | 공유받은 성장 순간 보기 | 원하면 한 줄 남기기 |
| 사진은 찍지만 정리하지 않는 사람 | 자기가 찍은 사진·영상 하나 보내기 | 기존 아이 기록에 연결 |
| 실제 돌봄을 함께 하는 사람 | 본인이 한 돌봄 내용 하나 남기기 | 배우자가 다시 물어보는 번거로움 줄이기 |
| 의견을 내는 사람 | 질문 하나에 경험이나 선택 이유 남기기 | 관심 주제 대화로 연결 |
| 적극적으로 기록하는 사람 | 직접 기록·챌린지 참여 | 커뮤니티 활동으로 확장 |

##### 먼저 시험할 한 가지

**가족이 보낸 성장 순간을 열고, 짧은 반응을 남기는 흐름**부터 시험한다.

- 신규 방문자에게 앱 설치부터 요구하지 않는다.
- 필요한 가족 접근 확인을 거쳐 공유받은 해당 화면으로 바로 연결한다.
- 설치 없이 이용한다는 것과 인증 없이 누구에게나 아이 사진을 공개한다는 것은 다르다.
- 다른 유형의 참여는 한꺼번에 전부 구현하지 않고 첫 실험 결과에 따라 판단한다.

##### 성공 조건과 주의점

- 보내는 사람이 사진을 여러 번 올리고 참여를 독촉해야 한다면 부담만 늘어난다.
- 가족의 한 줄 반응과 경품을 결정하는 투표는 분리한다.
- 아이 사진은 기존 공개 범위를 지키고, 가족 초대의 철회·만료가 가능해야 한다.
- 댓글을 남겼다는 것과 실제 돌봄을 분담했다는 것은 다른 결과다.
- 초대 열람, 반응 완료, 두 번째 이용, 주 기록자의 부담, 카카오톡 대비 실제 선호를 관찰한다.
- 소수의 사용성 시험만으로 남편 전체의 이용 성향이나 커뮤니티 성공을 입증하지 않는다.

**남편 참여가 낮더라도, 주로 이용하는 보호자에게 충분한 가치가 있으면 서비스는 성립할 수 있다. 남편의 가입 여부를 다다맘 전체의 성공 조건으로 만들지 않는다.**

#### 6. 이미 만든 기능을 살리는 방법

| 현재 자산 | 앞으로의 역할 | 우선 보완할 부분 |
|---|---|---|
| **커뮤니티** | 서비스의 중심 | 월령·상황이 맞는 글 발견, 답변, 이후 후기 |
| **성장 기록** | 혼자 써도 남는 가치 | 질문·사진·후기를 필요할 때 기록으로 연결 |
| **챌린지** | 첫 참여와 재방문의 계기 | 성장 순간을 가볍게 남기는 경험, 결과의 공정성 |
| **가족 공유** | 기존 이용자가 가족을 초대하는 통로 | 설치·입력 부담과 중복 업로드 줄이기 |

기능을 삭제하라는 뜻은 아니다. **홈에서 모두를 같은 크기로 강조하지 말고, 첫 방문자의 행동을 하나로 좁힌다.** 기존 기능 접근은 유지한다.

##### 챌린지의 역할과 검증

현재 챌린지의 응원·투표 경쟁은 참여를 만들 가능성이 있지만, 지인 동원 부담이나 인기 경쟁으로 느껴질 위험도 있다. **경품 없는 성장 기록에도 다시 참여하는지**를 함께 확인한다. 경품 참여자 수만으로 커뮤니티 수요를 판단하지 않는다.

점수·순위·자격·경품 규칙을 이 제안서만으로 바꾸지 않는다. 회원에게만 보이는 참가작을 홍보 목적으로 임의 공개하지 않는다. 가족 열람·커뮤니티 노출·외부 홍보 활용은 각각의 공개 범위와 동의를 지켜야 한다.

#### 7. 한 달 실행 계획

목표는 ‘완성’보다 **다시 쓰는 이유**를 확인하는 것이다. 아래 인원과 기간은 시장 평균이나 성공 기준이 아니라 다다맘을 위한 실행 제안이다.

##### 첫째 주 — 대상과 첫 경험을 좁히기

- 첫 모집 대상으로 **생후 6~12개월 아이를 키우는 보호자**를 제안한다.
- 이유식, 수면, 기기, 외출 등 질문과 성장 이야기를 함께 다루기 좋다는 가설이다.
- 가장 수요가 크다고 입증된 선택은 아니며, 실제 모집 반응에 따라 바꿀 수 있다.
- 게시판을 여러 개 더 만들기보다 한 피드에서 월령과 주제로 글을 찾게 한다.
- 초기 이용자가 여러 빈 공간으로 분산되지 않도록 한다.
- 첫 화면에서 무엇을 할 수 있는지, 글에 어떤 반응을 기대할 수 있는지 명확히 한다.

##### 둘째 주 — 적은 인원으로 사용상의 막힘 고치기

- **5~8명**에게 가입, 글 찾기, 작성, 답변, 가족 공유를 실제로 해보게 한다.
- 여기서는 커뮤니티 성공 여부를 판단하지 않는다.
- **사람이 있어도 못 쓰게 만드는 불편**을 찾는 단계다.
- 막힌 화면과 이유를 기록하고, 핵심 흐름의 오류부터 고친다.

##### 셋째·넷째 주 — 실제 대화와 재방문 확인하기

- 같은 시기의 보호자 **30~50가구**를 목표로 제한 모집한다.
- 이 숫자로 전체 시장을 검증할 수는 없지만 서로의 이야기에 반응하는지 관찰할 수 있다.
- 질문 → 답변 → 이후 후기, 성장 기록 → 재방문, 가족 초대 → 추가 행동을 관찰한다.
- 경품이 있는 활동과 없는 활동을 구분해 결과를 본다. 이용자 특성·주제·시점이 다를 수 있으므로 단순한 차이를 인과 효과로 단정하지 않는다.

##### 모집 경로

출처를 구분해 측정할 수 있는 경로를 사용한다.

1. 먼저 협의한 육아 수업·문화센터 등의 안내 QR
2. 참여에 동의한 소규모 육아 콘텐츠 운영자
3. 예산 상한을 둔 소액 광고

무단 커뮤니티 홍보를 전제로 잡지 않는다. 제휴 요청·연락·광고 집행은 실제 담당자가 별도로 실행할 일이며, 문서 작성이나 개발 요청을 외부 발송·지출 승인으로 해석하지 않는다.

##### 확인할 지표

| 지표 | 확인하려는 문제 |
|---|---|
| 가입 후 첫 글·댓글까지 완료하는가 | 첫 이용이 어렵거나 쓸 이유가 약한가 |
| 운영자 외 다른 이용자의 답변이 붙는가 | 실제 상호작용이 생기는가 |

| 경품 없이도 다시 기록·대화하는가 | 보상이 없어도 가치가 있는가 |
| 가족 초대가 추가 행동으로 이어지는가 | 초대 기능이 실제로 도움이 되는가 |

초기 운영자가 답변을 돕는 것은 필요할 수 있다. 대신 운영자임을 밝히고, 실제 회원처럼 보이는 가상 글·댓글로 활동량을 꾸미지 않는다. 그래야 무엇이 부족한지 정확히 알 수 있다.

##### 한 달 뒤의 판단

- 재방문과 자발적인 대화가 생기는 주제가 있으면 해당 대상·흐름에 집중한다.
- 글은 읽지만 작성하지 않으면 작성 부담, 공개 부담, 답변 기대, 주제 적합성을 먼저 점검한다.
- 경품 활동만 이용되면 이를 일반 커뮤니티 수요로 해석하지 않는다.
- 가족 초대 반응이 약하지만 주 이용자가 재방문하면 가족 기능의 우선순위를 낮춘다.
- 반응이 약할 때마다 새 기능을 더하기보다 모집 대상·유입 경로·처음 제시한 가치를 재검토한다.
- 정해진 표본·기간만으로 사업 성공이나 실패를 확정하지 않는다.

#### 8. 사업화 순서

다다맘에는 브랜드관과 챌린지가 있으므로, 첫 사업화 가설로 **작은 브랜드와의 주제형 협업**이 연결하기 좋다.

예를 들어 실제 이유식 이야기가 오가는 이용자가 모였을 때, 관련 브랜드와 협의해 제품 체험을 진행하고 사용 경험을 받는 방식이다. 광고·협찬 표시와 솔직한 후기 조건을 분명히 한다. 긍정적인 후기 작성을 혜택 조건으로 강제하지 않는다.

**브랜드관이 있다고 바로 광고가 팔리는 것은 아니다.** 먼저 ‘어떤 보호자가 들어와 무엇을 하고 다시 오는지’ 보여줄 근거가 필요하다. 그 전에는 큰 경품, 많은 상품 입점, 복잡한 결제 기능에 비용을 늘리지 않는 쪽을 권한다.

실행 순서:

1. 핵심 이용 흐름을 정상화한다.
2. 좁은 대상의 실제 이용과 재방문을 확인한다.
3. 관찰한 활동을 근거로 작은 제휴를 협의한다.
4. 협업 결과와 이용자 경험을 평가한다.
5. 반응이 있는 부분에만 다음 개발비·홍보비를 배분한다.

- 당시 공개 커뮤니티에서 임신·육아·익명 탭과 글에 표시된 시기 정보를 확인했다. 글 상세에는 관련 인기 글과 쇼핑 연결이 있었다. 같은 시기 이야기를 찾아 대화하고 관련 상품을 접하는 흐름을 참고할 수 있다.

- 다다맘은 당시 웹에서 로그인 창을 통해 참여하는 흐름이 있었다. 공유받은 글 → 인증 → 원래 글 복귀 → 댓글까지의 마찰을 줄이는 것이 검증할 기회다. 이것만으로 지속적인 경쟁 우위가 입증된 것은 아니다.
- 공개 인기 글의 높은 조회·댓글은 선택된 사례다. 평균 반응, 월간 이용자, 다다맘의 예상 성과로 환산하지 않는다.

근거: [공식 홈](https://babybilly.co/ko), [공개 커뮤니티](https://babybilly.co/ko/home/community-list).

### 14-2. 성별각도법 AI를 주력으로 삼지 않기로 한 이유

- 베이비빌리의 당시 AI 성별 테스트 랜딩을 확인했고, 시작 화면에서 초음파 사진 업로드와 선택적 태명 입력을 관찰했다. 실제 사진을 업로드하거나 예측 결과·정확도·전체 결제 흐름까지 검증하지 않았다.
- 비슷한 도구를 추가한다고 독점적 유입이나 재방문이 생긴다고 볼 수 없다. 일회성 호기심 유입이 질문·대화·기록으로 이어지는지가 별도 가설이다.
- 임상 초음파 연구의 정확도를 사진 업로드 AI의 정확도로 옮겨 주장하지 않는다. 마케팅용 높은 정확도 수치를 새로 만들어 넣지 않는다.
- 개발한다면 사진 적합성 확인과 판정 보류, 개인 식별정보 가림, 분석 목적과 커뮤니티 공개의 분리, 보유기간·삭제·학습 활용 여부 확인이 선행 조건이다. 이 문서는 개발 지시가 아니다.
- 운영사의 공개 개인정보처리방침만으로 이 AI의 구체적인 모델·처리업체·사진 보유기간·학습 이용을 확정하지 못했다. 초음파 사진이 학습이나 광고에 쓰인다고 추정해 단정하지 않는다.

근거: [당시 확인한 AI 랜딩](https://babybilly.co/ko/landing/gender-test), [운영사 개인정보처리방침](https://babybilly.co/policy/ko/privacy).

### 14-3. 마미톡 — 초음파라는 구체적인 진입 계기

- 병원에서 녹화한 초음파 영상을 확인하고 가족에게 공유하는 기능이 공식 앱 소개에 나온다. 커뮤니티를 쓰기 전에도 앱을 열 필요가 생긴다는 점을 참고한다.
- 시기별 정보, 수유·수면·배변 및 성장 기록, 커뮤니티, 쇼핑·체험단·클래스가 이어진다. 다다맘이 이 기능 목록을 전부 따라 만드는 것은 운영 범위를 크게 늘릴 수 있다.
- AI 베이비매직은 미래 아이 모습 이미지 상품으로 소개돼 있다. 성별각도법 예측과 같은 기능으로 섞어 설명하지 않는다.
- 광고성 ‘국민앱’ 문구나 앱 평점을 사용자 전체의 만족도·실제 이용률 증거로 삼지 않는다. 현재 정확한 매출·수익 배분은 확인하지 않았다.

근거: [마미톡 공식 앱 소개](https://apps.apple.com/kr/app/id1494440076?platform=ipad).

### 14-4. 맘가이드 — 구매 결정을 돕는 명확한 사용 목적

- 제품 성분·자체 등급·랭킹·실사용 리뷰를 통해 무엇을 살지 결정하는 상황을 겨냥한다. 화장품·세정제·물티슈·식품 등 제품 비교의 목적이 분명하다.
- 다다맘 브랜드관도 단순 상품 진열보다 실제 이용자의 상황과 경험을 연결하는 쪽을 가설로 검토한다. 지금 별도 성분 평가 시스템을 구축하라는 뜻은 아니다.
- 맘가이드 자체 등급을 정부 인증·개별 아이의 적합성·의학적 안전 보장으로 표현하지 않는다. 회사 소개의 제품 수와 성분 수는 운영사 주장으로 구분한다.
- 핫딜·광고 접점은 확인되지만 정확한 수수료·광고 매출은 추정하지 않는다.

근거: [맘가이드 공식 앱 소개](https://play.google.com/store/apps/details?hl=ko&id=kr.co.pushapp.momguide).

### 14-5. 맘맘 — 갈 곳·살 것이라는 당장의 필요

- 공식 웹에서 아이와 갈 곳, 숙소, 어린이집·유치원, 육아템 랭킹, 템 공유, 꿀팁, 혜택 메뉴를 확인했다. 장소 탐색·예약·구매가 연결되는 구조다.
- 다다맘의 나들이·브랜드관을 같은 규모로 늘리기 전에 해당 정보를 유지·검증·제휴할 운영 여력이 있는지 판단한다. 초기에는 중심 커뮤니티의 보조 정보로 두는 방향을 추천했다.
- 당시 공식 멤버십 안내는 월 결제 10,000원과 9,900포인트 적립을 구분했다. 이를 현금 월 100원 상품이라고 단순 설명하면 안 된다. 포인트의 사용처·유효기간 제한도 확인해야 한다. 가격은 2026-10-29 공개 안내 기준이며 실제 결제 검증이나 현재 가격 보장이 아니다.
- 거래액·예약액을 회사 매출·이익으로 해석하지 않는다.

근거: [맘맘 공식 웹](https://mom-mom.net/), [당시 멤버십 안내](https://mom-mom.net/shop/membership/intro?places=undefined).

### 14-6. 베이비타임 — 공동 기록은 실용적인 필요에서 출발

- 공식 앱 소개에서 수유·수면·기저귀 기록, 성장일기, 위젯, 엄마·아빠·도우미의 공동 기록을 확인했다.
- 남편 참여를 단순 사진 감상에만 한정하지 않고 ‘마지막 수유가 언제인지’, ‘내가 한 돌봄을 다시 설명해야 하는지’처럼 당장 필요한 정보에서 검토할 수 있다.
- 다다맘에는 이미 돌봄 기록이 있으므로 중복 기능을 추가하기보다 현재 기능이 실제 부담을 줄이는지 확인하는 것이 먼저다. 경쟁 앱의 전체 동기화 신뢰성을 직접 시험한 것은 아니다.

근거: [베이비타임 공식 앱 소개](https://play.google.com/store/apps/details?hl=ko&id=yducky.application.babytime).

### 14-7. 패밀리앨범과 카카오톡 — 사진 공유의 실제 대안

- 패밀리앨범은 초대받은 가족의 열람, 월별 정리, 댓글·반응, 사진 관련 상품·구독을 제공한다. 공식 안내에 브라우저 열람도 있어 ‘가족이 설치 없이 본다’는 기능만 독점 차별점으로 삼기 어렵다.
- 부모가 사진을 보내고 상대가 빠르게 답하는 상황에서는 카카오톡도 직접 비교할 대안이다. 다다맘을 거치면서 업로드·가입·공유 단계가 더 늘어나는지 확인해야 한다.
- 다다맘의 차별화 가설은 기존 기록 하나가 또래 부모의 대화·이후 후기·가족의 짧은 참여로 이어지는 흐름이다. 기록자의 부담이 실제로 줄고 가족이 다시 참여하는지 검증한다.
- 가족 열람 수를 실제 돌봄 분담 증가나 남편 전체의 참여율로 해석하지 않는다.

근거: [패밀리앨범 공식 웹](https://family-album.com/), [공식 브라우저 안내](https://blog.family-album.com/blog/how-to-share-an-album-on-iphone/), [구독 기능](https://family-album.com/premium).

### 14-8. 다다맘의 당시 실제 상태와 차별화 시 주의점

- 당시 웹 메뉴에는 홈·챌린지·커뮤니티·브랜드관·매거진·나들이·MY가 있었다. 현재 구현은 최신 저장소에서 다시 대조한다.
- 첫걸음, 만삭·D라인, 할로윈, 뒤집기·배밀이, 볼살 등 챌린지가 있었다. 과거 추첨 방식 설명을 그대로 적용하지 않는다. 당시 소스의 월별 점수·투표 구조를 확인했지만 이 인수인계가 규칙 변경을 승인하지는 않는다.
- 참가작은 회원 전용 열람이었다. 이를 유입 확보 목적으로 공개 링크나 공개 사진 미리보기로 바꾸지 않는다.
- 당시 챌린지 안내에 SNS·광고 활용 기간 관련 조항도 있었다. 회원 전용 열람만을 근거로 ‘사진이 외부에 절대 사용되지 않는 서비스’라고 홍보하면 안 된다. 공개·분석·가족 공유·마케팅 활용 목적과 동의/철회를 서로 구분해 검토한다.
- 글 작성에는 협찬 표시와 민감 사진 가림 기능이 있었다. 이를 삭제하거나 무력화해 참여 장벽을 낮추지 않는다.
- 웹 글 주소는 `community.html#/p/<id>` 형태였고 공유 미리보기 메타데이터는 공통이었다. 검색 유입·글별 공유 미리보기 개선은 별도 기술 검토 대상으로 남겼다. 인증·사진 보호를 우회하지 않으며, 단순히 #만 지우면 검색 문제가 해결된다고 보지 않는다.
- 테스트 게시물 수·조회·댓글은 가상/시드일 수 있다. 이를 실제 이용자 성과나 브랜드 영업 자료로 쓰지 않는다.

### 14-9. 차별화 검증의 판단 기준

1. 사용자가 다른 부모의 답변 때문에 다시 오는가?
2. 질문 이후의 결과·변화를 자발적으로 남기는가?
3. 경품이 없어도 기록·대화가 생기는가?
4. 배우자 초대가 기록자의 추가 노동 없이 참여로 이어지는가?
5. 기존 카카오톡 공유보다 다다맘에 남길 이유를 사용자가 설명하는가?
6. 실제로 반복되는 행동이 확인된 부분에 다음 개발비와 홍보비를 집중할 수 있는가?

남편 전용 커뮤니티, 가족 앨범, 성별각도법 AI를 모두 중심에 두지 않는다. 초기에는 좁은 대상의 커뮤니티·기록 흐름을 검증하고, 이 파일 13절의 한 달 계획과 12절의 남은 P0 실행 범위를 함께 따른다.

# 홍보 효과 측정 — 운영자용 SQL

분석 도구 없이 두 가지만 남깁니다 (`supabase/migrations/0015_signup_from_last_seen.sql`).

| 컬럼 (`profiles`) | 내용 | 언제 남나 |
|---|---|---|
| `signup_from` | 처음 들어온 주소의 `?from=` 값. 없으면 `null` | 프로필이 **처음 만들어질 때만**. 이후 바뀌지 않음 |
| `last_seen` | 마지막으로 앱을 연 **날짜** (한국 날짜, 시각 없음) | 로그인한 사람이 앱을 열 때 하루 한 번 |

## QR 주소 만들기

```
https://adultryun188-lang.github.io/dadamom-app/?from=<시설코드>
```

- 시설코드는 **영문·숫자·하이픈, 32자 이내** (예: `cafe-songdo1`, `clinic-a`). 그 밖의 값은 버려집니다.
- 기기에 **처음 들어온 값**만 기억합니다. 같은 사람이 다른 QR 을 나중에 찍어도 바뀌지 않습니다.
- QR 은 **웹 주소**로 걸어야 합니다. 플레이스토어로 바로 보내면 `from` 이 실리지 않습니다.

## 1) 채널별 가입 수

기간은 시험 기간으로 바꿔 쓰세요. 날짜는 한국 날짜 기준입니다.

```sql
select coalesce(signup_from, '(경로 없음)') as 가입경로,
       count(*)                            as 가입수
  from public.profiles
 where (created_at at time zone 'Asia/Seoul')::date between '2026-10-20' and '2026-11-02'
 group by 1
 order by 2 desc;
```

## 2) 가입 후 다시 온 비율 (7일 근사치)

```sql
with c as (
  select coalesce(signup_from, '(경로 없음)')             as 경로,
         (created_at at time zone 'Asia/Seoul')::date     as 가입일,
         last_seen
    from public.profiles
   where (created_at at time zone 'Asia/Seoul')::date between '2026-10-20' and '2026-11-02'
     -- 가입 후 7일이 다 지난 사람만 센다 (아직 기회가 없었던 사람을 빼기 위해)
     and (created_at at time zone 'Asia/Seoul')::date <= (now() at time zone 'Asia/Seoul')::date - 7
)
select 경로,
       count(*)                                         as 가입,
       count(*) filter (where last_seen > 가입일)        as 다시옴,
       round(100.0 * count(*) filter (where last_seen > 가입일) / count(*), 1) as "재방문율(%)"
  from c
 group by 1
 order by 2 desc;
```

### 이 숫자는 근사치입니다

- **`last_seen` 은 마지막 날짜 하나만 남습니다.** 그래서 위 값은 정확히 "7일 안에 다시 왔나"가 아니라
  **"가입 다음 날부터 조회한 날까지 한 번이라도 다시 왔나"** 입니다.
  가입 7일째에 조회하면 둘이 같고, 늦게 조회할수록 8일째 이후 처음 온 사람까지 섞여 높게 나옵니다.
  가입일이 2주에 걸쳐 퍼져 있으면 **조회일을 "마지막 가입일 + 7일"로 고정**하고,
  사람마다 관찰 기간이 7~21일로 다르다는 점을 감안해 채널끼리 비교하는 용도로만 쓰세요.
- **하루 단위**라 가입한 날 다시 연 것은 세지 않습니다.
- 날짜는 **휴대폰의 날짜**로 남습니다 (한국 사용자면 한국 날짜). 가입일은 서버 시각을 한국 날짜로 바꾼 값입니다.

### 무엇을 "가입"으로 세나

- `profiles` 행 = **아이 정보 입력까지 마친 사람**입니다. 이메일 가입만 하고 아이 정보를 넣지 않은 계정은 세지 않습니다.
- `from` 은 **QR 로 연 그 브라우저**에 남습니다. 아이폰에서 Safari 로 열었다가 "홈 화면에 추가"한 앱에서 가입하면
  저장소가 달라 `(경로 없음)` 으로 잡힐 수 있습니다.
- 웹 커뮤니티(`community.html`)만 들르는 것은 접속으로 치지 않습니다. 앱(`index.html`)을 열 때만 갱신합니다.
- 운영자·테스트 계정은 보통 `(경로 없음)` 에 섞입니다. 필요하면 `where id not in (...)` 으로 빼세요.

## 운영 이관 시 주의

- **DB(0015)를 코드보다 먼저** 적용하세요. 새 코드는 프로필을 저장할 때 `signup_from` 을 보내므로,
  컬럼이 없으면 **프로필 저장 자체가 실패**합니다 (콘솔에 `[다다맘] 프로필 저장 실패` 가 찍힘).
- 기존 회원의 `last_seen` 은 `null` 로 시작합니다. 이관 후 처음 앱을 열 때 채워집니다.
- `last_seen` 갱신은 기존 트리거 때문에 `profiles.updated_at` 도 같이 바꿉니다. 지금 `updated_at` 을 읽는 곳은 없습니다.

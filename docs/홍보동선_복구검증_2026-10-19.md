## 3. 로컬 검증 결과

### 스텁/함수/UI 회귀

명령: `RUN_BASELINE=1 node tests/community-flow.spec.mjs` (환경변수 문법은 셸에 맞게 사용).

- 신규 검증 **70개 통과**. 이 숫자에는 기존 E2E 전체 성공 확인 1개가 포함된다.
- 기존 `tests/e2e.spec.js`도 별도로 전체 통과. 320/360/390/430px, PWA 자원, 게스트 접근 제한, 스크랩·알림·가입 경로·기기 프로파일 등을 확인했다.
- 기존 이메일 로그인 복귀, 미완성 프로필 저장 후 복귀, 가입 인증 대기와 콜백 URL, 실패 시 재시도 동선을 스텁으로 확인했다.
- 외부·우회·중복 복귀 URL, 미공개 공유 제한, 출처 코드 처리와 인증 파라미터 전달 방지를 함수 수준에서 확인했다.
- JavaScript 문법 및 `git diff --check` 통과.
- 그래프 도구는 HTML 내부 동작을 충분히 색인하지 못했다. 영향도 0이라는 출력을 안전성 증거로 삼지 않고 실제 소스·브라우저 검증을 수행했다.

### 실제 테스트 DB + 로컬 UI

명령: `LIVE=1 node tests/community-flow-live.mjs`.

- **17개 통과**: 실제 이메일 로그인 후 원글 복귀, 댓글 저장, 상단·하단·DB 숫자 일치, 좋아요·북마크 저장, 정확한 공유 목적지, 대기 글 공유 차단·비로그인 접근 제한, 다른 화면 로그아웃 후 앱 알림창 닫힘.
- 일반 테스트 계정만 사용했다. 관리자 계정·새로운 승인 작업·스키마 조작은 하지 않았다.
- 가상 댓글·검수 대기 글을 생성·삭제했고 재조회로 삭제를 확인했다. 좋아요·북마크는 검증 전 상태로 복구했다.
- 기존 공개 글 본문·검수 상태·기존 댓글은 변경하지 않았다. 접속 날짜 등 기존 정책에 따른 기록까지 지운 것은 아니다.

## 6. 남은 한계·운영 반영 전 확인

- 실제 신규 계정 생성·인증 메일 수신은 실행하지 않았다. 신규 가입 관련 결과는 스텁 검증이다.
- 테스트 환경 소셜 로그인은 비활성화다. 카카오·구글의 실제 왕복 인증 및 리다이렉트 허용 목록은 별도 테스트 환경에서 확인해야 한다. 운영 설정을 바꾸지 않았다.
- 실제 아이폰 Safari·인스타그램 인앱 브라우저·OS 공유 시트는 미검증이다. 자동 기기 프로파일은 실기기 검증과 다르다.
- 복사 검증은 브라우저가 Clipboard API에 전달한 문자열을 검사했다. OS 클립보드·다른 앱 붙여넣기까지 검증한 것은 아니다.
- 실시간 채팅·휴대폰 푸시·D7 유지율·광고 성과를 추가하거나 검증하지 않았다.
- 공유 권한 제한은 사용자 안내용 보완이며, 실제 접근 통제는 기존 테스트 DB의 RLS가 계속 담당한다.
- 운영 승격은 별도 사용자 승인과 `docs/PROMOTION.md` 절차가 필요하다. 이 작업에 운영 반영 승인은 없다.

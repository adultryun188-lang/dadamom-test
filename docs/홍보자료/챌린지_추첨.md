# 첫걸음 챌린지 경품 추첨 — 12/3 (2026-10-20 준비, Claude)

앱에 적힌 약속: **"참가하면 추첨으로 4명에게 2만 원 상당 육아용품 · 11/30 마감 · 12/3 발표 · 당첨되면 가입한 이메일로 연락"**
(`index.html` `#challenge-prize`, 마감 `CHALLENGE_DEADLINE = '2026-11-30'`)

## 규칙 (SQL 이 이대로 고른다)

- 대상: **검수 승인된** 참가작, **11/30 23:59(한국 시간)까지** 올린 것
- **한 사람 한 번**: 참가작을 여러 개 올려도 추첨 기회는 1번 (계정 기준)
- 운영자 계정(`admin_emails`)은 뺀다
- 탈퇴한 사람은 자동으로 빠진다 (계정이 없으면 join 에서 빠짐)
- 섞는 방법: `md5(계정ID + 추첨 문구)` 순서. 같은 문구로 다시 돌리면 **같은 결과**가 나온다 → 나중에 "왜 내가 아니냐"는 문의에 같은 결과를 보여 줄 수 있다.
  추첨 문구는 **돌리기 전에 정해서 공지**에 같이 적는다 (예: 아래 SQL 의 `'2026-12-03 다다맘 첫걸음 추첨'`). 결과를 보고 문구를 바꾸면 안 된다.

## 1. 12/1 이후 — 검수 대기 비우기

11/30 까지 올라온 참가작 중 검수 대기(`pending`)가 남아 있으면 추첨에서 빠진다. **12/2 까지 관리자 화면에서 전부 승인·반려.**

```sql
-- 남은 검수 대기 수 (0 이어야 추첨)
select count(*) from public.challenge_entries
 where status = 'pending' and created_at < timestamptz '2026-12-01 00:00:00+09';
```

## 2. 12/3 — 추첨 (운영 Supabase › SQL Editor, 사장님)

읽기만 하는 SQL 이다. 결과 화면을 **캡처해 보관**한다 (당첨 증빙).

```sql
with seed as (select '2026-12-03 다다맘 첫걸음 추첨'::text as s),
eligible as (
  select e.owner_id, count(*) as entries
    from public.challenge_entries e
    join auth.users u on u.id = e.owner_id
   where e.status = 'approved'
     and e.created_at < timestamptz '2026-12-01 00:00:00+09'
     and lower(coalesce(u.email,'')) not in (select lower(email) from public.admin_emails)
   group by e.owner_id
)
select row_number() over (order by md5(el.owner_id::text || seed.s)) as 순서,
       p.nickname as 닉네임, p.region as 지역, el.entries as 참가작수,
       u.email as 연락메일,
       (row_number() over (order by md5(el.owner_id::text || seed.s)) <= 4) as 당첨
  from eligible el cross join seed
  join auth.users u on u.id = el.owner_id
  left join public.profiles p on p.id = el.owner_id
 order by 순서
 limit 8;
```

- 1~4번이 당첨, **5~8번은 예비** (당첨자가 12/10 까지 회신이 없으면 5번부터 차례로).
- 참가자가 4명 이하이면 전원 당첨.
- 카카오 가입자는 메일이 비어 있을 수 있다(카카오는 이메일을 안 받음). 그러면 **앱 공지 + 커뮤니티 댓글**로 연락하고, 회신은 운영 메일로 받는다.
- 테스트 DB 에서 2026-10-20 돌려 봄: 테스트 참가작 1건 → 1명 당첨으로 정상.

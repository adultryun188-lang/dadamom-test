### 1-2. 합당성 판단

판단 기준 (스크립트에 규칙으로 넣음):
- **가입 1명 값**: 01의 업계 범위 8천~4만 원, 03 목표 1.6만(1단계)·2만(2단계) → 8천 미만 쌈 / 8천~2만 합당 / 2만 초과 비쌈.
- **재방문 회원 1명 값**: 기준선 = 목표 1.6만 ÷ 앱 평균 7일 재방문 12%(01 0-3) ≈ **13.3만 원**. 이하면 합당, 절반 미만이면 쌈.

| 예산안 | 판단 | 근거 |
|---|---|---|
| 기존 20만 | **비쌈** | 가입 1명 3.1만(목표의 2배), 메타가 끝까지 학습을 못 끝냄, 참가작 2개로 대회 화면이 빔. 돈을 아끼는 게 아니라 버리는 구간 |

| 공격 600만 | **합당 (단가가 가장 쌈)** | 1.4만. 단, 네이버 검색·제작자 단가는 근거가 가장 약한 가정이고, 실측 전 600만 원을 거는 위험은 03 판단과 같음 |

**기획 목표와 비교 — 고쳐야 할 것 하나**:
03의 1단계 목표(**2주 안에 가입 120·참가작 60**)는 권장안으로 달성 확률이 각각 **3%·0%** 입니다. 권장안 14일째 중간값은 가입 88·참가작 36입니다. 03 6-2의 한 달 예상(가입 214)은 시뮬레이션(188)과 비슷하지만, 그 한 달 숫자를 2주 목표로 옮겨 적은 것으로 보입니다.
→ 이 문서는 **1단계 목표를 "2주 가입 90·참가작 35", 다음 단계 기준을 "참가작 35 + 참가율 25%"** 로 바꿔 씁니다. 03의 120·60은 **한 달(11-10~12-09) 목표**로 옮깁니다(권장안 한 달 중간값 188·65로 충족). [가정: 숫자만 현실에 맞춘 것이고 전략은 그대로]

**한계**: 가정끼리 독립으로 뽑았습니다. 실제로는 소재가 나쁘면 클릭률과 가입률이 같이 나빠집니다. 전부 나쁘면 권장안 가입 47명·1명 6.3만 원까지 떨어집니다. 그래서 4절의 "끄는 기준"이 꼭 필요합니다.

## 5. 매주 점검 지표와 판단 규칙

### 5-1. 매주 월요일 성과표 (Claude가 만들어 사장님께)

| 숫자 | 어디서 | 계산 |
|---|---|---|
| 채널·광고별 지출, 노출, 클릭, 랜딩 조회 | 메타·당근 관리자 화면 (사장님 캡처 또는 내보내기) | — |
| 경로별 가입 | SQL ① | `profiles.signup_from` |
| 경로별 승인 참가작·참가율 | SQL ③ (아래, 조회문만 추가) | 참가한 가입자 ÷ 가입 |
| 경로별 7일 재방문 | SQL ② | 근사치 (`last_seen` 한계, 홍보_측정.md) |
| **가입 1명 값** | 지출 ÷ 그 경로 가입 | 광고별로 |
| 검수 대기 24시간 넘은 글 | 관리자 화면 | 0개여야 함 |

SQL ①②는 `홍보_측정.md` 그대로, 기간만 바꿉니다. ③은 새로 쓴 조회문입니다 (DB 변경 없음):

```sql
-- ③ 경로별 참가율 (승인된 참가작 기준)
select coalesce(p.signup_from, '(경로 없음)')                  as 가입경로,
       count(*)                                                as 가입,
       count(*) filter (where e.n > 0)                         as 참가한사람,
       round(100.0 * count(*) filter (where e.n > 0) / count(*), 1) as "참가율(%)",
       coalesce(sum(e.n), 0)                                   as 승인참가작
  from public.profiles p
  left join lateral (
        select count(*) as n from public.challenge_entries c
         where c.owner_id = p.id and c.status = 'approved') e on true
 where (p.created_at at time zone 'Asia/Seoul')::date between '2026-11-10' and '2026-11-23'
 group by 1
 order by 2 desc;
```

### 5-2. 판단 규칙
